# M05 人工确认与事务：模块规格

继承 ../../requirements.md 的需求与固定设计，不另立生命周期、来源或授权规则。

## 需求与失败路径

- **R06 六决策与确切最终视图**：作为知识生产者，我需要 create/update/merge/split/deprecate/defer 及 no_change，以固定来源、相关基线、稳定 ID/替代关系形成完整 ChangeSet 和拟落位 stable 最终字节。
  失败边界：同名或同来源不自动合并；循环/断裂替代、重复 ID、缺证据应拒绝或 defer；确认 draft 后不得另补未经确认字段。
- **R07 人工文档确认与门禁豁免**：作为文档贡献者，我可以本人确认最终卡、来源集合与范围；manual_document 以真实人工决定生效并沿用到共享，不要求 LocalCheckRecord/MergeGateRecord。
  失败边界：无回复/超时/Agent 自报不是同意；部分接受须重建最终视图再确认；字节、来源、scope 或相关基线变化使旧确认失效；当前代码承诺不能借 raw 免门禁。
- **R08 并发安全的事务落位**：作为并行维护者，我需要领域写锁、相关基线 CAS、全库 ID/替代引用一致性、备份与 journal，使已确认内容完整落位且中断可恢复。
  失败边界：不能只比 touched_paths 漏掉别处同 ID；证明陈旧/外部修改时保留双方；回滚只恢复仍为本次写入字节的目标，消费者不读半套文件。
- **R15 可恢复编排与显式发布授权**：作为使用者，我需要生产/治理 Workflow 以同一 operation、基线与 final-view 摘要交接，区分能力 Skill、编排、检查、合入和发布责任。
  失败边界：同名入口不遮蔽/递归；等待或返回修订核摘要，已 apply 不重复写；索引失败只恢复索引；无上库授权停在本地，CI 不隐式运行生产。
