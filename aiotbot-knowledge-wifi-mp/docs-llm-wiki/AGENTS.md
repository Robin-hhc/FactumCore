现行名称和目录以架构设计 §5.3 为准，用户后续明确决定优先。唯一领域根为 `aiotbot-knowledge-wifi-mp/`；项目根的 `skills/common/knowledge/` 存节点能力，`workflows/common/knowledge/` 承载 ingest 端到端编排。两者与根 AGENTS/config 同级管理。Git 在 FactumCore 根执行，不建立嵌套 `.git` 或隐藏能力目录。

架构设计解释分层与协作；详细设计分概要和节点设计两层，以流程图、分支条件和文件职责表达。设计正文不记开发轮次、票据状态、Agent 工作进度或历史测试成绩；这些进入 SDD 工件。系统设计不构成正式领域事实，Schema/Contract 机器规则归 `../governance/`，此处不另建执行契约。

统一约定：一条 ingest 完整串起 P1 扫描／续办、P2 材料、P3 阅读计划、P4 写稿及必要确认／代码语义核验、P5 调用 lint Skill、P6 登记处理记录、P7 本地入库、索引全验与目标查询，通过后 ingest 结束；仅记录批保存记录后结束，不再分前后两段。详设 §3.1 展开 lint 的 L1—L5 只读检查；它可被 ingest、手动或定期调用，只检查和报告。等待真人或材料时按原操作与视图续办。Git 提交、触发 CI 和合入均是人工后续流程，不属于 ingest 的完成条件。C1 直接复用 lint 的已有固定脚本和确定性函数，通过后由人合入，不调用 Agent，不另开发业务构建任务。源码分析按确切源码和逐 Claim 条件核验，不统一强制编译产物；具体产品当前实现核对真实 Target 和条件；编译、运行或实测断言须对应证据。本地原件核对确切捕获对象，不要求先有 Git 提交；跨机恢复与 CI 输入由人工上库时准备。索引构建不另拆维护、激活或发布交接主线；现有模板与实际调用边界仍按使用说明和源码核实。

代码内容判断由独立 Agent 阅读与复核，记录作者回避、独立上下文、逐 Claim 理由和依据；固定脚本只校验记录结构、引用和确切视图／源码绑定，不要求复核者公钥或密码学签名。纯文档真人确认和共享发布回执仍按各自规则验证，不混成代码复核的额外接入条件。

实现修改前读取对应 SDD 需求、设计、任务和测试计划，依据实际验证更新记录。保留历史工件原字节，不批量替换旧记录路径或状态。普通文档整理不读受限 gold。纯文档真实确认、本地代码只读核验与固定 CI、五类原件及未知业务上下文遵循上级 AGENTS。

不新增 research、experiments、agents、superpowers 或设计文档子目录。系统设计优先维护现有两份主文档；操作写使用说明，任务、测试、发布与历史记录写相应 SDD 工件。
