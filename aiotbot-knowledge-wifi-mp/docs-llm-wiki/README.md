项目自身的 `task.md` 与 `sdd/` 仅在本地保存开发任务、需求、测试计划和验收记录，已由 Git 忽略；共享仓库和能力包不包含这些工件，使用与部署无需准备它们。

文档用 `repo/` 表示项目根目录的示意名称。业务代码工作区、`AGENTS.md`、`config.yml` 与知识库 `aiotbot-knowledge-wifi-mp/` 位于该根目录。开发仓的 `skills/common/knowledge/` 和 `workflows/common/knowledge/` 是分发源码；部署到 Agent 自己的最终目录后，由知识库 `tools/deploy/` 登记实际位置，运行不要求项目根保留能力目录。业务代码可包含多个实际代码仓或模块目录，不另建嵌套 `.git`。本目录只存系统说明与开发工件，正式领域知识只进入 `../knowledge/`。

项目架构映射由 `config.yml` 提供，知识库与代码位于同一业务工作区。独立存放知识库需要另行完成宿主部署适配，增加连接配置并不会扩展这个数据布局。普通业务 CLI 不隐式读取 `config.env`；只有显式 `run_node.py --config-env` 读取私有执行配置。路径与数据布局见[工作区路径与部署边界](知识库关键点.md#1-工作区路径与部署边界)。

同一工作区内的知识根可按 `knowledge_roots.wifi` 嵌套，项目根以确切 `config.yml` 为准。服务器工作区统一通过 SSH 执行完整节点及子 CLI，不经 Samba／UNC／映射盘运行或遍历项目；真正本机磁盘部署可直接运行。调用端使用本机磁盘上的 Python 和部署工具副本，服务器使用原生路径。配置和远端产物边界见[执行说明](../tools/deploy/EXECUTION.md)。

执行器显式读取机器本地 `config.env`（模板在 `tools/deploy/config.env.example`）配置连接，不以它替代项目架构映射。首次配置、字段、取回 catalog、请求与调用及升级步骤集中在[使用说明](使用说明.md#选择-windowslinux-或-ssh-执行)。服务器工作区的 SSH 要求不以性能报告为前置；测量结果只说明对应操作和环境的收益。能力字节变化后在执行端重新登记，再通过 SSH 更新调用端 catalog 副本。

`config.yml` 维护代码根和模块相对路径，以及芯片、Host／Device、特性和用途；共享模块可关联多芯片、多端。无需逐项填写六 Target、三 pair 或重复代码根授权，取证按路径读取实际文件并固定内容指纹。配置填法见[使用说明](使用说明.md#配置项目代码架构)，共享映射与核验逻辑见[知识库关键点](知识库关键点.md#1-工作区路径与部署边界)。

能力共 19 个 Skill：18 个公开 CLI 节点及 1 个纯说明 `hs-codegraph-setup`，另有 1 条 ingest Workflow。首次 setup 按真实模块准备图谱及宿主官方 MCP，空模块列表不建图；日常 Q6 直接使用官方 MCP 或实际文件检索。卡头 `Claim.source_refs` 及查询恢复的来源已能提供模块、文件与定位，Agent 据此匹配实际 `config.yml` 的模块根后追查源码，不以正文可点击链接为前提；操作见[查询和追代码](使用说明.md#3-怎么查询和追代码)，边界见[详细设计 §5.9](知识库详细设计.md#59-q1q6路由查询同代精读与回答)。

设计文档描述职责、流程与边界，能力安装、实际宿主、六 Target、CI 合入和权限验证以各自环境的实际记录为准。本项目历史验证工件在本地 SDD 保存原始版本身份，不据此推断当前部署状态。

详设中的 `knowledge ...` 是统一入口名称。部署完成后，按[使用说明](使用说明.md)向 Agent 点名调用 Workflow 或 Skill；底层接口参数见相应能力的 `SKILL.md` 与 `references/`。

`knowledge ingest` 默认扫描五类允许 raw 并选择新增、变化及待处理来源；`--source` 仅为限制本次范围的可选参数，首次导入和日常增量使用相同入口。

日常入口 `ingest` 用一条工作流完成扫描、写稿、独立内容复核和适用代码核验、调用 lint、登记处理记录和本地入库，`query` 消费正式知识。`hs-knowledge-lint` 是可复用的只读检查 Skill，既供 ingest 调用，也可手动或定期检查；发现问题由 ingest 返回对应节点修订，暂停后按原操作续办。

文档与代码内容均由独立 Agent 在不同于作者的上下文中阅读原件／源码及稿件，代码结论另记录逐 Claim 理由；脚本校验记录、引用和确切内容绑定，不要求复核者公钥或密码学签名。lint 与 CI 继续只检查确定性项。

用户可在执行中要求退回，也可在入库后要求修改已有卡；原件未变的明确修订仍走新操作，重新完成复核、检查与入库。

本地入库、完整索引验证、本批目标查询通过，且该代次成功激活后 ingest 结束；之后由人提交并触发固定 CI，复用 lint 的格式、导航、引用和索引检查脚本，通过后人工合入；见[上库流程](知识库详细设计.md#32-上库固定-ci-检查后合入)。

`hs-workspace-explore` 是业务命令之前的保底发现能力：Agent 未加载项目约定，或独立 Workflow 节点尚不知道仓内知识库、代码图谱和入口时才补齐信息；已有上下文直接复用，不属于生产 P1 或各命令必调节点。
