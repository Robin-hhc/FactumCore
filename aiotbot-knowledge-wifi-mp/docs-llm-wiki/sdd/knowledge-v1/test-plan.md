# 测试、审查与验收计划

## 验证层级

| 层级 | 输入与入口 | 能证明什么 | 不代替什么 |
|---|---|---|---|
| SDD 一致性 | tools/validate_sdd.py、固定设计摘要、traceability.json | 需求、模块、路径、任务和验收引用闭合，DAG 无环 | 代码功能与真实覆盖 |
| 合成机制 | pytest、临时 Git/导出目录、fixture 配置/卡/记录；公开 CLI | 确定性输入输出、错误诊断、摘要绑定与边界分支 | 真实 WiFi 行为、人工动作真实性、宿主选择 |
| 链路集成 | 后续生产/治理/消费 Workflow 与 acceptance runner | 固定输入上完整三链路、故障恢复 | 目标环境部署和实际语义 |
| 宿主验证 | T24，固定全局 Skill/宿主版本、registry 与仓内入口，在目标 Agent 新会话中仅给代码路径 | 可见、选用、正确绑定、实际加载及分析前加载率 | 代码单测或“Skill 已安装” |
| 业务验证 | T25，六 Target/三 pair 的真实源码、构建、宏、协议与运行证据 | 对应范围实际成立的结论 | 共享源码同 hash、逻辑目录或模拟工程 |
| 外部边界 | T26，获准环境的跨组访问与撤销负测 | 外部执行环境实际拒绝未经授权访问 | AGENTS/config/文件夹分类 |

用户级 AGENTS 由用户自行配置，不开发或托管，也不将其交付或加载作为宿主验收前提；测试保留全局 Skill 可见性、有限 registry 定位和仓内 AGENTS 的实际读取轨迹。

## 首批 T01/T02

T01 从实际 CLI 验证 workspace/card/sources/record 的合法/缺字段/错版本、七 Profile、unknown 不冒充部署、跨芯片 pair/重复 ID/悬空引用、Schema 篡改/远端引用/越界路径、畸形或重复 YAML、统一退出信封与只读输入。条件匹配测试完整组的 AND/OR、缺字段 unknown、宏排除与协议版本；这不是逐断言证据资格判断。

T02 用实际临时 Git 仓、worktree 和无 Git 目录测试任意 cwd/中文空格/相对基准、路径边界、歧义、显式嵌套覆盖、登记摘要过期、实际入口读取及返回正文、checkout 身份、变化后重核、规则版本与零业务写入。Windows 用目录联接验证真实路径绕转，权限不支持的方式如实报告，不以跳过当通过。公共 CLI 必须在默认 Windows 管道编码下返回可解码 JSON。

对应 E01/E02/E05/E07/E08/E32 仅覆盖首批声明或机制部分；原设计各项的其余义务仍由后续 ticket 完成。没有执行的 E03/E04、语义门禁、部署或外部验证不因测试总数增加而关闭。

## 开发与审查门槛

每个行为先实际 red，记录功能缺失与环境故障的区别；后者不能当作 red 证据。针对测试 green 后跑受影响全套、ruff、compileall、SDD 一致性和 FactumCore 本任务 diff 检查。pytest 显式使用 workspace artifacts/test-tmp 下独立目录，保留公开输入和实际运行记录，不读受限 gold。

审查分两个独立维度：实现是否符合仓内边界/规范；实现是否满足当前 ticket/原设计、不扩大承诺。发现有据缺陷先补复现、修正后重跑。验证记录保存实际环境版本、命令、结果和限制，不能伪造源码核验、人工确认或发布身份。

## 首发退出条件

T01–T28 的相应行为和证据齐备；E01–E34 按原始输入与预期记录结果；三类证据（框架机制、宿主触发、真实六 Target/外部部署）分别成立。三条未来 sources 路径不作为首发功能。未具备外部条件的票保持待验，不用合成测试成绩代替。
