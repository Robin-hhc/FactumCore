# Agent 内容复核与固定脚本校验

用户明确：代码知识的独立内容复核由 Agent 在 ingest 内完成，脚本检查确定性项；删除额外的 reviewer 公钥登记与密码学签名报告门槛。纯文档真人确认、人工提交与固定 CI／合入边界不变。

| 对象 | 调整后职责 |
|---|---|
| 独立复核 Agent | 阅读原文／源码、计划、卡与最终视图，逐条说明结论的依据与条件，指出问题；作者修订，复核者重新核对受影响部分 |
| 代码复核记录 | 保存作者、复核者、独立上下文声明、确切视图／代码上下文、逐 Claim 结论及理由、来源定位和指纹；不要求公钥或签名 |
| 本地固定校验 | 核对实际作者集合、记录完整性、未解决问题、确切视图、逐条来源／产物与配置条件的一致性；不认证主体身份，不证明语义正确 |
| 入库、查询与维护 | 复用同一记录校验与当前源码身份检查；内容或来源改变后旧记录不覆盖新内容，不因未登记签名密钥而阻断 |
| 真人确认与发布 | 保留纯文档的真实确认要求；发布与共享回执的现有真实性检查不属于本次代码复核调整 |

报告沿用 `semantic_review` 名称，表示 Agent 的内容复核记录；新产物的验证类别明确为 `agent_content_review`。身份、独立上下文和判断由执行者声明，脚本可拒绝作者冲突、缺字段、未解决问题、漏 Claim 或绑定失配，不能据此声称认证了真实 Agent 身份或内容语义。

实施顺序：公开无密钥记录的失败用例 → 去除代码复核验签并补齐声明／依据校验 → 下游完整入库、索引与查询／维护回归 → 独立复核与真实旧源码试验。旧原件、历史记录和既有验收成绩保持原字节，不静默补字段或重签。

完整回归 21 组、380 项，**379 通过、1 跳过、0 失败／错误**；跳过项为当前 Windows 账号没有普通符号链接创建权限，junction 与越界拒绝用例实际通过。核心／统一契约定向 37 项、无密钥下游全链 4 项分别通过，不累计到完整回归用例数。统一契约同时验证无签名 Agent 记录合法、无签名真人事件仍拒绝；Ruff 与 `git diff --check` 通过。

独立标准轴复核发现共享 Schema 仍把真人事件和代码复核放在同一签名分支，已拆开并让本地节点实际调用统一 Schema；该中途回归保留原记录，修复并刷新规则后重新跑完全部组。规格轴无阻断，另有一处旧认证措辞的注释已更正，并验证可执行 AST 不变。主详设 40 个本地链接／锚点、22 个 Mermaid 解析通过；唯一改动的 P4 图实际渲染通过，2.1 主图和 Workflow 拓扑未变。

真实源码试验在新隔离知识根完成 **1 卡、4 Claim** 的独立复核、lint、P6 记录、P7 本地入库、索引激活、目标查询及同代读取。复核者实际读取三份 GB18030 源码、计划与稿件，指出两处原首稿缺失条件：UP 背景扫描不一定切换 VAP 状态，超时找不到 VAP 会提前返回。作者在新候选中补齐并重新复核；原首稿、旧审查报告、源码和 `main/` 导出保持原字节。新普通复核记录没有签名，安装 catalog 没有配置代码复核者密钥，也没有借用合成信任标记。

用户试验需求原件只作为触发与处理范围，未作为技术事实来源；P6 如实记录部分覆盖、没有伪造整份已采用。上述结果只覆盖历史 Host HMAC 扫描卡，不代表 592 份代码全部提炼、真实产品 Target／编译／设备运行、自动宿主 Workflow 接入或整项语料效果验收。
