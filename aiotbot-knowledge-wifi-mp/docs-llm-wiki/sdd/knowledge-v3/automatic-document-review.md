# 文档知识自动复核与入库

用户决定取消 ingest 中的真人前置确认。用户可在执行中要求退回，也可在本地入库后要求 Agent 修订；不再以真人回复、宿主签名事件或展示 challenge 作为文档 stable 的条件。本约定补充原始基线和此前内容复核约定，历史记录保留原字节。

## 实现要求

- 删除 `hs-knowledge-confirmation-prepare`、`hs-knowledge-confirmation-record` 和 Workflow 用户确认 gate；安装目录保留 18 个 Skill 和 1 条 ingest Workflow。
- 文档稿经独立 Agent 内容复核和完整 lint 后进入 P6／P7；混合稿继续完成代码部分逐 Claim 核验。保留现有 `manual_document` 协议值表示文档类，它不再代表人工批准要求。
- 文档入库依据为已有 `content_review`，绑定确切操作、最终视图和作者计划，检查作者回避、独立上下文和无未解决问题。混合稿使用全视图内容复核及代码证明，不再组合真人证明。
- 移除真人事件信任配置、验签、展示记录、时效与模板等专用逻辑；共享发布回执保留自身职责。入库继续核对来源恢复、最终完整 lint、精确字节及旧基线 CAS。
- 原件未变时，用户修卡请求仍是 P1 的待办；P2 显式选择对应单元和已有卡，P3 标记本次 content 修订，P4 仍纳入独立复核。旧卡的确切对象由材料包提供给 lint 和入库检查，用户无需先提交 Git 或手工准备历史指纹。
- 退回、材料不足和执行中断保留实际停点；内容改变以新操作重新复核和检查。已入库内容按新变更修订，不改写旧事务或重放旧入库。事务恢复和回滚保护外部修改。
- ingest 仍以本地入库、完整索引验证及本批目标查询通过为完成条件；人工提交、固定 CI 和合入在其后进行。

文档、混合稿及现行 V3 代码批继续执行完整固定检查与来源恢复；旧非 V3 纯代码批保留原 local-check 和 checked-snapshot 语义。本次删除文档真人门，不改变该兼容代码路径。
