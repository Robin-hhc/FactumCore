# 需求与实现差异

设计依据和指纹见 [baseline.json](baseline.json)。本表先于生产修改建立，覆盖当前实现，不限于 Git diff。已有安全能力可复用，不以重写数量衡量完成度。

| ID | 规格与当前差异 | 验收边界 |
|---|---|---|
| R301 | E0 仍被固定为 ingest 的 bind_project；安装器固定旧双 Workflow | E0 按需先执行，ingest 直接 P1，三个逻辑入口有明确分派，保留宿主安装与触发的区别 |
| R302 | source-capture 必填单文件，缺默认增量发现 | P1 五类 raw 全扫，固定清单、范围和完整性，对照共享记录与停点识别新增/改动/缺失/未完成/读取错误；局部扫描不推断范围外删除 |
| R303 | 缺 P2 关联材料和逐卡采用版本 | 来源反查、主题候选、明确依赖；包含维护所需各状态；每卡取实际采用旧版及新材料，候选不等于修改决策 |
| R304 | plan 先收卡稿，缺逐 Claim 裁决与实质 skip 抽查协议 | Agent 逐条记录事实/条件/依据/保留与拟改；合卡单一写者，目标查询可追踪；独立风险抽查覆盖和未抽范围可验证 |
| R305 | 单一 review_mode 拒绝混合批，检查与确认拆在旧 lint Workflow | P4 分区完成代码独立复核和文档确切视图真人确认，变更失效重做；保留已有真实签名与证据保护 |
| R306 | candidate-inspect 含写调用，缺共享 CheckReport 与 lint Skill | 全视图只读 L1—L5，稳定码、范围、N/A/未完成、退出 0/1/2；预检/lint/CI 共用纯函数 |
| R307 | records 仅通用 seal，缺唯一共享处理记录 | 固定清单逐项对账、分段覆盖、observed/adopted/progress、来源/Claim 真实绑定；skip/defer/失败事实不伪造检查或同意 |
| R308 | apply 只接受卡/nav/lock；缺批记录同事务和提交前门禁 | 控制记录写集合并入原 CAS/journal；apply 后 index 全验及本批目标 query 通过才准提交；记录批走独立无卡路径；收尾重试不重复入库 |
| R309 | 索引构建私有，verify 仅摘要/正文；来源与上下文限制依赖本机事实 | 共用构建/全量逻辑核验，集合/行值/版本/分词/正文一致；当前来源/代码/配置/规则差异影响 Claim 资格，保持同代检索与阅读 |
| R310 | check.py 调旧语义 merge-check，拒绝纯文档且依赖私有 .build | 固定可信 runner 对候选数据做格式、索引、来源/代码引用检查，缺输入失败，不调用 Agent 或导入候选程序 |
| R311 | 当前测试、入口文档仍冻结 18 Skill/2 Workflow | 更新当前使用与验收入口，历史字节和原成绩保留；真实宿主等外部能力不由 fixture 证明 |
