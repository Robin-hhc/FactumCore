## 发现的问题

本机正向 search 约 36.2–36.5 秒，read 约 36.2–36.7 秒。耗时按输入／输出文件时间估算，包含公开节点启动和校验，未做分段性能分析，不能归因于 SQLite 查询本身。

第一题 search、read 各有 32 次直接子节点调用：30 次来源恢复、2 次入库结果核验。10 个来源定位来自 3 个文件，每个定位分别解析 3 遍。来源恢复结果重复携带完整原件，单次最终输出约 1.31 MB。

对应查询程序 `hs-knowledge-query/scripts/node.py`：search 的首次资格检查、新 Evaluator 检查及输出前来源刷新分别恢复来源；read 的资格检查、刷新及新 Evaluator 检查也各恢复一次。当前按完整来源定位缓存，不共享同一文件的不同定位读取。公开调用同时重新核对能力包和规则。后续需结合多卡及变更／失效用例统一设计优化，不在本次试查中绕过检查或修改实现。
