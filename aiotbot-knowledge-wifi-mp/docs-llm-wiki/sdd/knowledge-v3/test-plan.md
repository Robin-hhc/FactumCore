# 验证计划

公开 Skill CLI / 固定 CI CLI 是主要验收入口。先保留 RED 证据，再修改生产实现并运行相关组；最后完整回归。期望值以合成原文、手写卡/Claim 和计划为独立基准，不从被测结果生成。

| 范围 | 必测行为 |
|---|---|
| P1/P2 | 无参全扫、增删改/未完成、局部范围不误删、读失败、越界/链接；同源两卡采用不同版本、全状态维护检索、明确依赖与普通链接区分 |
| P3/P4 | 逐 Claim 变更与保留、单写者、多原件融合、冲突/缺证 defer、实质 skip 风险抽样/未抽范围；混合稿分区、真人确切视图、变更失效 |
| P5/CI | 完整合成视图、frontmatter/Profile/ID/锚点/链接/来源/代码定位/关系/全索引，稳定 findings、范围、N/A 与 0/1/2；只读及候选程序不可执行 |
| P6/P7 | 漏项/重复/清单外/分段覆盖、observed/adopted区分、真实关联；同一CAS/中断恢复/外改冲突；索引或目标查询未过禁止提交；仅记录不夹带卡稿 |
| 索引/query/M | 缺/多/错行、Claim/元数据/关系/分词/规则版本、同代正文、资格先于topK、当前引用变化；Windows 长路径；不新增暂缓的索引过期检查 |
| 回归与发布边界 | 当前全部 Skill tests 和 evals/tests 独立进程；当前 Workflow loader/目录安装与逻辑分派；设计/历史指纹原字节保持；不把合成结果当真实外部验收 |

跨接口补充：实际 capture-code 的已提交代码必须经过新 P7 strict 门禁、真实索引及本批目标 query/read，不能手改 recovery 后宣称成功。共享待办须在同一 query 已正向命中过的前提下，实际 P6/P7/Git 落位 defer、删除本机状态、保持原件不变后仍阻断。CI 历史引用测试同时覆盖首个提交虚构卡拒绝、旧卡更新后旧记录可恢复以及缺历史对象未完成。

运行环境：仓库现有 Python 3.12 虚拟环境；临时目录位于领域 `artifacts/test-tmp/`。既有 `evals/run_acceptance.py` 每组独立进程，保存 stdout/stderr、JUnit XML 和总表。真实宿主触发、真实人、六 Target、远端 CI、跨组 ACL 不在本地 fixture 结论内。
