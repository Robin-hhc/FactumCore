# 2.0 运行记录与独立内容复核

所有机器记录使用 schema_version 2.0、准确 record_kind 和规范对象摘要。节点记录绑定 operation、规则摘要、实际 Skill 包及运行依赖身份。摘要只检测内容和绑定变化，不认证执行者身份，不提供权限。

文档类与代码类稿件均在 P4 完成独立 Agent 内容复核；`content_review` 保存确切计划／最终视图指纹、复核者、独立上下文及问题清单。文档的 `manual_document` 是保留的分类取值，不要求真人动作、宿主签名、展示 challenge 或确认记录。作者回避、逐 Claim 依据和未解决问题继续校验；文档类不调用 local-check/merge-check。

代码卡由独立 Agent 阅读源码并记录逐 Claim 理由和正支持依据，再生成 LocalCheck。缺少当前结论实际需要的路径、配置或证据则保持 incomplete；历史／指导性源码结论允许未知 Target 和构建信息，但不得推广为具体产品当前适用或已编译运行。编译、运行或实测断言仍须有相应证据。apply 通过 local-check 的公开 verify-proof 入口复核记录，不接受任意自报 passed。

P7 重新验证完整 lint、确切视图及独立内容复核；混合批再验证代码部分。可提交验收摘要的文档和代码结论均记录 supported，退役记录 retired，来源／代码上下文和实际复核记录指纹一并绑定。旧人工确认记录不代替当前独立复核。纯记录批用 admission_record 绑定原件处理记录及空写删视图，不授权知识内容写入。

用户可在流程中要求退回、暂缓或修订；稿件内容、来源、规则或相关基线变化后生成新操作并重新复核。已入库卡的后续修改走新操作，旧操作和处理记录保留。无回复不会制造用户同意，也不再是 ingest 的等待条件。缺少材料、内容复核失败或固定检查未通过仍保存真实停点。

事务 journal 记录完整 writes/deletes、expected-old／最终摘要、持久备份及每步结果。committed 重入返回原结果；非终态先受控恢复。发生外部新编辑时停止并保留现场，不覆盖编辑来完成恢复。索引和维护记录独立绑定代次、当前事件 epoch 及两水位，索引回滚不能撤销当前阻断。

共享发布回执继续按实际发布身份与受信签名核验，它与本地内容复核是不同边界。真实宿主 Workflow 触发、六 Target、CI 合入与权限部署各有独立验收；Schema、包测试或合成数据不能代替。
