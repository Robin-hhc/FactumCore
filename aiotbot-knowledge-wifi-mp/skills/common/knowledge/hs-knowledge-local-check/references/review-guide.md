# P3/P4 内容复核

主 Agent 阅读原文、各卡实际采用的旧版、旧卡全文和计划；脚本不根据关键词代替内容判断。独立复核者使用新的上下文，只读复核材料，不担任同一卡的作者。

1. 逐 Claim 比较事实、适用芯片、Host/Device、版本、宏和构建条件。设计要求与实现事实分别表述；代码图谱只提供定位，结论核对真实定义、调用与条件。
   `verification_requirements` 按结论选择：`semantic-support` 核静态源码及条件，无需先取得编译产物；`build-support` / `runtime-support` 分别要求真实构建／运行证据。测量结论必须有运行证据。后两类在逐 Claim 复核记录内提供 `verification_evidence`，每项的 `requirement`、`path`、`sha256` 须绑定上下文已固定的证据文件；只有源码语义支持不能冒充编译或运行成功。未知要求保持未完成。已有 Target 核真实映射及必要条件；缺 Target 仅允许 `historical` / `guidance`、unknown 且无 context 分组的源码知识，不推广到已登记六 Target。
2. 检查多源重叠是否归到同一卡、互补是否保留、冲突是否先排除适用范围差异。已有主题优先 update；独立新主题才 create。merge/split只是组织动作，逐条交代旧 Claim 去向；整卡职责均失效才 deprecate。
3. 对本批新／改原件的实质 skip 及 new/update 归属按风险抽查，优先数值、强制条件、跨芯片推广、删除／冲突原件和候选关系复杂项。读取被抽单元对应原文、旧卡及计划；记录抽查理由、已抽范围、未抽范围、问题、位置与依据。未抽项不能标为复核通过。P1 未变且已完整处理的扫描跳过无需重审。
4. 漏提炼、错归、范围错误返回 P2/P3；材料不足明确 defer。格式、导航或视图表达错误回 P4。作者修订后复核受影响部分，不沿用已变内容的裁决。
5. P4核对完整卡稿、导航和来源登记是否忠于计划，包括保留部分和欠账。实质变更的代码结论需要独立于作者的复核；纯文档遵循相同审阅准则，并取得真实人对确切最终视图的明确动作。

`change-plan --action review` 固定声明的独立上下文及风险样本。`local-check` 校验独立 Agent 的逐 Claim 复核记录：作者与复核者声明分离、实际计划／卡作者对应、确切视图与代码上下文绑定、理由和来源定位完整、没有未解决问题。它不认证主体身份，也不证明宿主确实创建了独立上下文或知识语义正确；不要求 reviewer 公钥登记或报告签名。纯文档的人动作继续由 confirmation 节点鉴真。无回复、超时、Agent 自报及空问题数组均不能代替真人同意或具体代码依据。

本地入库、索引验证与目标查询完成即结束 ingest；人工随后提交、触发固定 CI 并合入。固定 CI 复用 lint 的格式、引用与索引检查，不重新进行内容复核，也不要求本节点执行 Git 提交或构建。
