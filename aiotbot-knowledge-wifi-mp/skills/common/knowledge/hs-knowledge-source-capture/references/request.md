# Capture and exact-source resolution

Capture request: `operation_id`, `source_path`, `source_id`; optional `version`, explicit `attachments`, `context_ref`. Only landed `docs-raw/{conventions,chips,storys,specs,protocols}` files are supported. Primary MD/TXT must be nonempty UTF-8, PDF needs a text layer on every page, DOCX supports paragraphs/tables with explicit visual gaps. No URLs, sources links, OCR, active content, network access or writes to originals.

Registered code request: `operation_id`, `kind:"code"`, `repo_id`, `relative_path`, `source_id`, `context_ref`. The protected catalog `code_policy.repo_roots` must agree with current workspace config and the receipt; a self-sealed receipt cannot authorize a root. The node freezes actual selected file bytes, including dirty Git bytes, with read-before/after checks and optional Git revision identity. Export revision is null and version stays unknown unless explicitly declared. No build, macro, Target applicability or semantic correctness is inferred. Repository programs, hooks, fsmonitor, external diff and textconv are not executed. Resource identities contain logical repo/path, not host root paths. Capturing code does not itself clear or infer semantic validity events.

For an authorized Git code checkout, when the selected committed HEAD blob exactly equals the captured bytes, the node automatically registers `recovery:{kind:git,method:git,repo_id,commit,path,status:available}` and verifies it through the common exact resolver. Dirty or export bytes remain local evidence and cannot pass v3 portable admission. A separate `local_recovery` retains the original local object for historical reading if present-day configuration or the Git object becomes unavailable; P7 invokes strict recovery with `allow_local_fallback:false` and never treats this fallback as cross-machine evidence. With no first-machine text/locator cache, supported code-utf8:1 extraction is rebuilt from the exact Git original and checked against its frozen text and locator fingerprints; incompatible extraction remains unavailable.

The configured WiFi root must match the explicit knowledge root. A supplied receipt `commit` or `head` must match actual Git HEAD; unknown remains unknown. Both capture and current-byte comparison verify actual Git top-level and a declared expected origin. Missing, mismatched or invalid present-day authorization yields null current status during historical recovery, while the exact retained evidence stays readable.

`--action resolve`: `operation_id`, `bundle_ref`; verifies retained original, extraction and locator digests. `--action resolve-source`: `operation_id`, `source_ref:{evidence_ref,source_id,snapshot_id,locator}` and optional candidate `bundle_ref`. Without a bundle, resolution uses the exact formally registered snapshot, never implicit latest.

The result includes `source_kind`, the logical `resource`, immutable original bytes, selected `text`, original locator, snapshot identity and limitations. `current_source_matches` is true/false/null after separately comparing current authorized source bytes. Missing code authorization returns null while retained historical evidence remains readable. A successful historical replay does not prove current applicability. MD/TXT and UTF-8 code use `lines` start/end; PDF uses `page`; DOCX uses `paragraph` or `table_row` with table/row. Opaque attachments return no interpreted text.

Machine code-change verification may use a code-only `bytes` locator with zero-based half-open start/end, including the empty range of an empty file. It returns `text:null` and exact original bytes with an explicit interpretation limitation; it does not assert a text location or positive semantic support.

Changed previously registered sources call the public `hs-knowledge-maintain --action register-source-change` before capture returns success. Missing maintenance installation blocks completion. Capture never writes sources.lock, formal cards or indexes.

For raw originals, capture automatically checks the configured workspace Git HEAD. Only when the exact committed blob equals the bytes read does it register `recovery:{method:git,kind:git,commit:<full object ID>,path:<workspace-relative file>,status:available}`. Otherwise it retains a local evidence object; drafting remains possible, while v3 publication reports the missing portable source. No commit, network fetch or service startup occurs.

Git recovery selects repository roots from the actual `config.yml`, never a source-supplied root. Raw paths stay within the five K raw directories; code recovery additionally requires a configured `repo_id`. Only fixed local commit/blob reads run, with lazy fetch, prompts, protocols and hooks disabled. Missing first-machine extraction caches may be reproduced from the exact Git original only when the frozen text and locator digests still match. Full old originals are distinct from current working-tree bytes.
