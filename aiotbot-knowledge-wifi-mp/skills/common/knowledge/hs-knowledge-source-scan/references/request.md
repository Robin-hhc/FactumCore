# Public request

Common inputs: explicit `operation_id`, known knowledge root, pinned rules and installed catalog. Optional Workflow run/node/attempt identities use the existing immutable manifest protocol.

- `scan`: optional `source` (raw file or directory relative to K), optional `prior_record_refs` only for explicit recovery; default reads formal `logs/ingest/*.yaml`. Returns sealed `scan_ref`/`scan_digest`, including exact scope and completeness. `new`, `changed`, `missing`, `unchanged`, `unfinished`, `read_failed` are observations, not semantic decisions. Incomplete scans never infer missing files.
- `prepare`: `scan_ref`; optional `unit_ids`, `topics`, `candidate_card_ids` and `code_bundle_refs:[{bundle_ref,bundle_digest}]`. Capture actual registered code first through public source-capture; prepare verifies exact code kind, bytes and current authorized identity before including immutable current code materials in the combined bundle. Returns `material_ref`/`material_digest` (`record_kind: artifact_manifest`, `purpose: source_materials`), current combined `bundle_ref`, candidate card paths/reasons and per-card actual source versions, immutable original copies, recovery/diff or explicit gaps. It includes `requires` and `derived_from` dependents across all card states, plus current-context affected cards even when raw bytes are unchanged. Candidate inclusion never chooses a card action.

  Each code source is captured under its own child `operation_id`, distinct from the ingest batch, without forwarding the Workflow object. A capture operation owns one immutable `capture.json`; prepare aggregates child bundle references into the batch operation's combined bundle. Reusing the batch ID for an individual code capture would collide with that aggregate, and reusing one capture ID for multiple code files is invalid.
- `record`: `scan_ref`, exact `dispositions` and applicable `plan_ref`, `view_ref`, `lint_ref`, `skip_sample`. Each disposition has `unit_id`, action/reason, observed/adopted fingerprints, progress, card_refs and claim_refs. Include explicit coverage, pending and next_step when incomplete. The proposed YAML is JSON-compatible YAML and contains the sealed inventory so other machines can understand it without local `.build/`. Returns `ingest_record_ref`, `record_ref`, digest and formal `record_path`; does not write the latter. P7 validates and applies it in the same batch as knowledge.

  When context Claims are affected, pass the bound `semantic_plan_ref`; P6 copies its separate `maintenance_units` into shared `maintenance_dispositions` and preserves defer/failure/uncovered pending facts. Each uses `maintenance:<card>#<claim>` and binds the exact `scan.current_context.affected_claims` set. These do not become raw units; code-only work can have an empty raw list.

- `status`: optional `target_operation_id`; returns actual saved local stage facts and explicit unverified submission/CI/merge state. It never repairs or resumes an operation.

Observed fingerprints and adopted versions are distinct. Unchanged input with unfinished processing or current-context restrictions remains actionable. Substantive skip uses `kind: substantive`; scan skips use `kind: scan_unchanged`. A record reports actual progress and does not itself approve the content or authorize Git publication. History follows explicit record predecessors per covered path; a narrow scan never erases earlier observations outside its scope, and conflicting branches remain unfinished.
