# M01 契约与运行基础：模块规格

继承 ../../requirements.md 的需求与固定设计，不另立生命周期、来源或授权规则。

## 需求与失败路径

- **R01 受信版本契约与稳定身份**：作为框架维护者，我需要同版受信的配置、七类卡、来源、记录与枚举契约，使所有入口解释相同字段，card/claim ID 不随路径漂移。
  失败边界：不兼容版本、损坏或未授权契约、远端 Schema 引用、重复 ID、断锚必须明确诊断；不能加载待审修改为自身放行。
- **R02 精确 WiFi 适用上下文**：作为 WiFi 研发者，我需要 chip12/chip08/chip07c × Host/Device 六 Target、三个同芯片 pair 及完整条件组，使结论仅适用于已经举证的芯片、侧别、宏、构建与版本。
  失败边界：unknown 不等于通用；组内 AND/组间 OR 不交叉重组；共享代码或缺一侧不能推出跨芯片/端到端成立。
- **R13 同代精读与有据限域回答**：作为查询用户，我需要精读固定代次正文、按定位回源并得到真实检索/读取收据，答案显示渠道、知识身份、claim、来源和实际证明/人工确认及缺口。
  失败边界：切 active 或改工作区不混读；仅 Host/设计文档不能推断全链路/实现/实测；无召回不证明无实现，未检索不伪造命中。
- **R16 授权边界与不可信材料**：作为项目 owner，我需要源码、原件、卡、索引、缓存、证据和端点均受同域实际授权约束，记录脱敏且来源内指令不成为执行/发布授权。
  失败边界：不借其他组权限，不把目录/AGENTS/config 称 ACL；权限撤销中止未交付内容；参数不执行为 shell/SQL，凭据/私有路径不流入共享。
- **R17 受控发行与真实宿主部署**：作为部署者，我需要固定框架/契约/工具来源和兼容版本，在实际 Windows/Agent 宿主安装全局 Skill 入口，并验证新会话选择、绑定和仓内入口加载轨迹。用户级 AGENTS 由用户自行配置，不纳入产品开发、安装或托管范围。
  失败边界：不自动安装/升级/追踪 master；有条件复用须满足许可/声明要求，否则独立实现；CLI 启动或目录存在不等于完整链路或稳定触发。
