# 评测集出题表（全组协作）

> **目的**：收集迭代开发中 Agent 必须胜任的真实场景，作为工具选型评测的基准题。
> **两类题**：
> - **NL→代码**：自然语言描述需求/问题/改动意图 → Agent 定位到相关代码
> - **代码→业务**：给一段代码 → Agent 讲清业务流程、设计意图、上下游
>
> **怎么填**：每人 3–5 题，从你日常开发中**真的会问**的场景出发。「你会怎么问」写原话即可，不用规范。
>
> **代码仓**：WiFi MAC 驱动（host/device 多仓，chip2/chip8 双 Target，C 代码，函数指针/ops 表/宏/Event-Message 机制）

## 评分规则

- **按难度计分**：易 = 1 分，中 = 2 分，难 = 3 分
- **关键点数量 = 难度**：易题 1 个关键点、中题 2 个、难题 3 个
- **每个关键点命中 = 1 分**，漏答部分流程也能拿部分分（如难题答对 2/3 关键点 = 2 分）
- 关键点要写成**可验证的独立事实**（"X 在 Y 模块的 Z 环节"、"设计原因是 W"），不要写"大概是这样"

## 出题参考

**NL→代码 好题**（有区分度，纯 grep 不一定答得对）：
- 加新功能："给 VAP 配置加 channel width 字段，从配置入口到硬件寄存器经过哪些环节？"
- 修 bug："5GHz 连接后 30 秒断连，跟 beacon 丢失有关，beacon 超时处理在哪个模块？"
- 影响分析："改 TX ring 的 ring size 从 256 到 512，会影响哪些地方？"
- 跨仓："host 侧 VAP 配置下发后，device 侧哪个环节接收处理？"
- 函数指针："TX ring switch 这个函数指针被谁调用？"（ops 表间接调用，直接 caller=0）

**代码→业务 好题**：
- 新人上手："解释 TX 主处理函数的完整业务流程，从收到上层数据到 DMA 发出"
- 设计意图："为什么 TX 用 ring buffer 而不是 linked list？ring size 256 怎么定的？"
- 跨模块："从 VAP 配置入口追踪完整链路，含 host→device 跨仓调用"
- 协议约束："802.11 要求 beacon 间隔 100ms，代码哪里保证？超时怎么处理？"

**避免的坏题**：
- "这个文件有哪些函数？"（纯结构，grep 就能答，无区分度）
- "这个函数是干什么的？"（指 5 行 getter，太简单）
- "项目架构是什么？"（太泛，不可验证）
- "帮我写个 XX 功能"（代码生成，不是代码理解）
