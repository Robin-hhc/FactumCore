# FactumCore 文档落点

本目录由原 docs/ 整体迁移而来，保存知识系统设计、开发 SDD、研究与实验材料，不保存正式业务知识卡。先按任务选择子目录；本轮批准的知识系统开发规格以 sdd/knowledge-v1 及其固定设计来源为准，研究 spec/design 保持原身份。

| 目录/文件 | 放什么 | 维护方式 |
|---|---|---|
| `设计文档/aibot.md`、`设计文档/知识库详细设计.md` | 本轮批准的总体设计与详设 | 先读同目录 README；部署决议为 FactumCore 单仓 |
| `设计文档/01–05` | 历史细化稿 | 依状态入口阅读，不用旧路径/字段覆盖当前知识契约 |
| `research/` | 来源调研、证据矩阵、比较及未实施方案 | 引用原始依据，注明版本、限制及建议身份 |
| `superpowers/specs/`、`superpowers/plans/` | 研究工程规格和执行计划 | 不冒充量产组件 spec/design/tasks 真源 |
| `sdd/knowledge-v1/` | 当前知识系统可执行开发规格、任务和实际验收 | 按需求、设计、ticket、测试与记录维护 |
| `experiments/` | 协议、试验设置及运行报告 | 实际测量才写成绩；协议与结果分别保存 |
| `workflows/` | 此前工作流方案 | 本轮可执行编排归仓根 workflows/，不重复建立规范源 |

同主题既有文件优先复用，跨目录职责变化需同步入口说明。向知识正文提炼时进入仓根 `aiot-wifi-knowledge/` 的治理流程；普通文档审阅不读取受限 gold。

不要把知识仓旧 `docs/架构设计.md` 当成此处新主稿的自动镜像。同步必须先比较新旧修改、确认覆盖范围并验证结果；仅更新导航不能宣称架构副本已经同步。
