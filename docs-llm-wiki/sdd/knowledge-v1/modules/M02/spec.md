# M02 项目发现绑定：模块规格

继承 ../../requirements.md 的需求与固定设计，不另立生命周期、来源或授权规则。

## 需求与失败路径

- **R03 仓外确定性发现与两阶段绑定**：作为从任意 cwd 开始的用户，我只提供代码路径，Agent 应解析真实 checkout 与已登记知识关联，实际读取入口后形成 context_loaded，并在环境变化后刷新。
  失败边界：无登记、多映射、同远端不同 clone/worktree、读取失败、路径前缀冲突不得猜选；resolved 不冒充已读取，切仓不沿用旧上下文。
- **R16 授权边界与不可信材料**：作为项目 owner，我需要源码、原件、卡、索引、缓存、证据和端点均受同域实际授权约束，记录脱敏且来源内指令不成为执行/发布授权。
  失败边界：不借其他组权限，不把目录/AGENTS/config 称 ACL；权限撤销中止未交付内容；参数不执行为 shell/SQL，凭据/私有路径不流入共享。
- **R17 受控发行与真实宿主部署**：作为部署者，我需要固定框架/契约/工具来源和兼容版本，在实际 Windows/Agent 宿主安装全局 Skill 入口，并验证新会话选择、绑定和仓内入口加载轨迹。用户级 AGENTS 由用户自行配置，不纳入产品开发、安装或托管范围。
  失败边界：不自动安装/升级/追踪 master；有条件复用须满足许可/声明要求，否则独立实现；CLI 启动或目录存在不等于完整链路或稳定触发。
