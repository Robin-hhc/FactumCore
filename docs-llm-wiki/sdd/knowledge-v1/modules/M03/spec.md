# M03 来源快照：模块规格

继承 ../../requirements.md 的需求与固定设计，不另立生命周期、来源或授权规则。

## 需求与失败路径

- **R02 精确 WiFi 适用上下文**：作为 WiFi 研发者，我需要 chip12/chip08/chip07c × Host/Device 六 Target、三个同芯片 pair 及完整条件组，使结论仅适用于已经举证的芯片、侧别、宏、构建与版本。
  失败边界：unknown 不等于通用；组内 AND/组间 OR 不交叉重组；共享代码或缺一侧不能推出跨芯片/端到端成立。
- **R04 实际字节快照与持久恢复**：作为知识生产者，我需要 Git 固定对象、dirty 工作区和无 Git 导出的实际读取字节、定位及持久恢复依据，使旧卡可按确切来源重放。
  失败边界：不以 HEAD 代替 dirty 字节，不为导出伪造 commit；来源不稳定、摘要/locator 不符或唯一证据不可恢复必须停止或报告缺口。
- **R05 首发仅 raw 实际原件**：作为文档维护者，我需要捕获 docs-raw 五类目录内已落地原件及必要附件，保留原字节、提取文本与页/章节映射。
  失败边界：sources 链接区、控制文件、URL、仓外映射、符号链接绕出及网页获取不进入首发；读取中变化、缺附件或解析失败不当作删除/成功，零网络获取。
- **R16 授权边界与不可信材料**：作为项目 owner，我需要源码、原件、卡、索引、缓存、证据和端点均受同域实际授权约束，记录脱敏且来源内指令不成为执行/发布授权。
  失败边界：不借其他组权限，不把目录/AGENTS/config 称 ACL；权限撤销中止未交付内容；参数不执行为 shell/SQL，凭据/私有路径不流入共享。
