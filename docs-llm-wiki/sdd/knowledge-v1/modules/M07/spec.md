# M07 代次索引与消费：模块规格

继承 ../../requirements.md 的需求与固定设计，不另立生命周期、来源或授权规则。

## 需求与失败路径

- **R02 精确 WiFi 适用上下文**：作为 WiFi 研发者，我需要 chip12/chip08/chip07c × Host/Device 六 Target、三个同芯片 pair 及完整条件组，使结论仅适用于已经举证的芯片、侧别、宏、构建与版本。
  失败边界：unknown 不等于通用；组内 AND/组间 OR 不交叉重组；共享代码或缺一侧不能推出跨芯片/端到端成立。
- **R11 渠道身份与不可变索引代次**：作为消费者，我需要 local 正常使用未合入 stable，shared 仅使用实际合入且确认/证明匹配的内容；索引和正文属于不可变 generation，经完整自检后条件激活。
  失败边界：不混 local/shared，不从丢失证明反造通过；构建/激活失败继续旧完整代，manifest 不自摘要，Windows 不覆盖使用中数据库。
- **R12 合格断言优先的可解释检索**：作为查询用户，我需要授权/渠道/purpose/scope/当前有效性硬过滤后召回和 top-k，支持原样精确符号、v3 中英文词项及可追踪排序。
  失败边界：错 Target/阻断断言不贡献候选、词频、摘要；重复 span/拆 claim 不抬分，非连续片段不拼短语，不以降权替代硬阻断。
- **R13 同代精读与有据限域回答**：作为查询用户，我需要精读固定代次正文、按定位回源并得到真实检索/读取收据，答案显示渠道、知识身份、claim、来源和实际证明/人工确认及缺口。
  失败边界：切 active 或改工作区不混读；仅 Host/设计文档不能推断全链路/实现/实测；无召回不证明无实现，未检索不伪造命中。
- **R14 当前失效阻断与双水位治理**：作为维护者，我需要来源/宏/构建/pair 变更沿 source→claim 和 requires/derived_from 传播，先持久化事件/影响/阻断，再分别推进扫描与知识应用水位。
  失败边界：related_to 不默认全域传播；修订失败不丢阻断，重放幂等；回滚索引不撤销当前阻断；精读/回源/输出前复查授权与事件。
- **R16 授权边界与不可信材料**：作为项目 owner，我需要源码、原件、卡、索引、缓存、证据和端点均受同域实际授权约束，记录脱敏且来源内指令不成为执行/发布授权。
  失败边界：不借其他组权限，不把目录/AGENTS/config 称 ACL；权限撤销中止未交付内容；参数不执行为 shell/SQL，凭据/私有路径不流入共享。
