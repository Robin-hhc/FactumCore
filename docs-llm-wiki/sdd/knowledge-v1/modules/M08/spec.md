## 需求与失败路径

- **R14 当前失效阻断与双水位治理**：作为维护者，我需要来源/宏/构建/pair 变更沿 source→claim 和 requires/derived_from 传播，先持久化事件/影响/阻断，再分别推进扫描与知识应用水位。
  失败边界：related_to 不默认全域传播；修订失败不丢阻断，重放幂等；回滚索引不撤销当前阻断；精读/回源/输出前复查授权与事件。
- **R16 授权边界与不可信材料**：作为项目 owner，我需要源码、原件、卡、索引、缓存、证据和端点均受同域实际授权约束，记录脱敏且来源内指令不成为执行/发布授权。
  失败边界：不借其他组权限，不把目录/AGENTS/config 称 ACL；权限撤销中止未交付内容；参数不执行为 shell/SQL，凭据/私有路径不流入共享。
