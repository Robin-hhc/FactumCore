# M09 Skills/Workflow与部署验收：模块规格

继承 ../../requirements.md 的需求与固定设计，不另立生命周期、来源或授权规则。

## 需求与失败路径

- **R03 仓外确定性发现与两阶段绑定**：作为从任意 cwd 开始的用户，我只提供代码路径，Agent 应解析真实 checkout 与已登记知识关联，实际读取入口后形成 context_loaded，并在环境变化后刷新。
  失败边界：无登记、多映射、同远端不同 clone/worktree、读取失败、路径前缀冲突不得猜选；resolved 不冒充已读取，切仓不沿用旧上下文。
- **R05 首发仅 raw 实际原件**：作为文档维护者，我需要捕获 docs-raw 五类目录内已落地原件及必要附件，保留原字节、提取文本与页/章节映射。
  失败边界：sources 链接区、控制文件、URL、仓外映射、符号链接绕出及网页获取不进入首发；读取中变化、缺附件或解析失败不当作删除/成功，零网络获取。
- **R07 人工文档确认与门禁豁免**：作为文档贡献者，我可以本人确认最终卡、来源集合与范围；manual_document 以真实人工决定生效并沿用到共享，不要求 LocalCheckRecord/MergeGateRecord。
  失败边界：无回复/超时/Agent 自报不是同意；部分接受须重建最终视图再确认；字节、来源、scope 或相关基线变化使旧确认失效；当前代码承诺不能借 raw 免门禁。
- **R10 最新代码只读合入检查**：作为 committer，我需要受信规则固定 H/B/T/V 与逐 claim reused/inherited/revalidated 证明，在最新业务代码观察点二次核验并于合入前重核有效性。
  失败边界：源码/规则/head/基线/必要 ref 或事件变化使证明过期；依赖不全不能继承；CI 零改卡、锁、链接和业务代码，不 apply/commit/push/激活。
- **R15 可恢复编排与显式发布授权**：作为使用者，我需要生产/治理 Workflow 以同一 operation、基线与 final-view 摘要交接，区分能力 Skill、编排、检查、合入和发布责任。
  失败边界：同名入口不遮蔽/递归；等待或返回修订核摘要，已 apply 不重复写；索引失败只恢复索引；无上库授权停在本地，CI 不隐式运行生产。
- **R16 授权边界与不可信材料**：作为项目 owner，我需要源码、原件、卡、索引、缓存、证据和端点均受同域实际授权约束，记录脱敏且来源内指令不成为执行/发布授权。
  失败边界：不借其他组权限，不把目录/AGENTS/config 称 ACL；权限撤销中止未交付内容；参数不执行为 shell/SQL，凭据/私有路径不流入共享。
- **R17 受控发行与真实宿主部署**：作为部署者，我需要固定框架/契约/工具来源和兼容版本，在实际 Windows/Agent 宿主安装全局入口和受托管薄规则，并验证新会话选择、绑定、加载轨迹。
  失败边界：不自动安装/升级/追踪 master；有条件复用须满足许可/声明要求，否则独立实现；CLI 启动或目录存在不等于完整链路或稳定触发。
- **R18 可执行且分层的交付证据**：作为验收者，我需要 E01–E34 的可重复输入、预期、实际与证据，分别汇报合成机制、宿主触发、六 Target/三 pair 真实业务及外部访问负测。
  失败边界：未执行、失败和通过分列；fixture 不冒充 WiFi 覆盖，协议不冒充成绩；不读取受限 gold，不把未来来源能力列首发已完成。
