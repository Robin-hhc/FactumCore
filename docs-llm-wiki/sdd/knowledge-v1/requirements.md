# 知识库首发 SDD 需求规格

依据现行《知识库详细设计》v2.0；本规格将既有设计展开为可追踪需求，不增加产品范围。按用户后续部署决议，逻辑 workspace 为 FactumCore 单仓，`aiot-wifi-knowledge/` 是仓根普通目录，文档根为 `docs-llm-wiki/`；原有 `aiot-knowledge/` 不迁移、不纳入本轮交付。

源文件 SHA-256：`c0ae815a7a48d2d3407c5f90e1a36e9beb73d8098322760093856b56b16c28d3`。共 18 项需求、149 条路径、34 项验收；未来来源 3 条单列 deferred。

## 1. 需求基线

### R01 受信版本契约与稳定身份

作为框架维护者，我需要同版受信的配置、七类卡、来源、记录与枚举契约，使所有入口解释相同字段，card/claim ID 不随路径漂移。

失败路径与边界：不兼容版本、损坏或未授权契约、远端 Schema 引用、重复 ID、断锚必须明确诊断；不能加载待审修改为自身放行。

责任模块：M01 契约与运行基础、M04 卡片与六决策。验收：E01、E03、E30。

### R02 精确 WiFi 适用上下文

作为 WiFi 研发者，我需要 chip12/chip08/chip07c × Host/Device 六 Target、三个同芯片 pair 及完整条件组，使结论仅适用于已经举证的芯片、侧别、宏、构建与版本。

失败路径与边界：unknown 不等于通用；组内 AND/组间 OR 不交叉重组；共享代码或缺一侧不能推出跨芯片/端到端成立。

责任模块：M01 契约与运行基础、M03 来源快照、M06 代码双门禁、M07 代次索引与消费。验收：E02、E08、E21、E23、E25、E31。

### R03 仓外确定性发现与两阶段绑定

作为从任意 cwd 开始的用户，我只提供代码路径，Agent 应解析真实 checkout 与已登记知识关联，实际读取入口后形成 context_loaded，并在环境变化后刷新。

失败路径与边界：无登记、多映射、同远端不同 clone/worktree、读取失败、路径前缀冲突不得猜选；resolved 不冒充已读取，切仓不沿用旧上下文。

责任模块：M02 项目发现绑定、M09 Skills/Workflow与部署验收。验收：E05、E06、E07、E08。

### R04 实际字节快照与持久恢复

作为知识生产者，我需要 Git 固定对象、dirty 工作区和无 Git 导出的实际读取字节、定位及持久恢复依据，使旧卡可按确切来源重放。

失败路径与边界：不以 HEAD 代替 dirty 字节，不为导出伪造 commit；来源不稳定、摘要/locator 不符或唯一证据不可恢复必须停止或报告缺口。

责任模块：M03 来源快照。验收：E04、E10、E15。

### R05 首发仅 raw 实际原件

作为文档维护者，我需要捕获 docs-raw 五类目录内已落地原件及必要附件，保留原字节、提取文本与页/章节映射。

失败路径与边界：sources 链接区、控制文件、URL、仓外映射、符号链接绕出及网页获取不进入首发；读取中变化、缺附件或解析失败不当作删除/成功，零网络获取。

责任模块：M03 来源快照、M09 Skills/Workflow与部署验收。验收：E09、E10、E14、E15。

### R06 六决策与确切最终视图

作为知识生产者，我需要 create/update/merge/split/deprecate/defer 及 no_change，以固定来源、相关基线、稳定 ID/替代关系形成完整 ChangeSet 和拟落位 stable 最终字节。

失败路径与边界：同名或同来源不自动合并；循环/断裂替代、重复 ID、缺证据应拒绝或 defer；确认 draft 后不得另补未经确认字段。

责任模块：M04 卡片与六决策、M05 人工确认与事务。验收：E03、E11、E17、E19。

### R07 人工文档确认与门禁豁免

作为文档贡献者，我可以本人确认最终卡、来源集合与范围；manual_document 以真实人工决定生效并沿用到共享，不要求 LocalCheckRecord/MergeGateRecord。

失败路径与边界：无回复/超时/Agent 自报不是同意；部分接受须重建最终视图再确认；字节、来源、scope 或相关基线变化使旧确认失效；当前代码承诺不能借 raw 免门禁。

责任模块：M05 人工确认与事务、M09 Skills/Workflow与部署验收。验收：E12、E13、E14、E17、E28。

### R08 并发安全的事务落位

作为并行维护者，我需要领域写锁、相关基线 CAS、全库 ID/替代引用一致性、备份与 journal，使已确认内容完整落位且中断可恢复。

失败路径与边界：不能只比 touched_paths 漏掉别处同 ID；证明陈旧/外部修改时保留双方；回滚只恢复仍为本次写入字节的目标，消费者不读半套文件。

责任模块：M05 人工确认与事务。验收：E13、E17、E18、E19。

### R09 确切最终视图的本地代码检查

作为代码卡贡献者，我需要只读检查拟落位 stable 的确切字节、来源、scope 与逐 claim 义务，通过后由独立 apply 落位并本地消费。

失败路径与边界：缺证据为 incomplete，矛盾为 fail；符号/hash/图边不替代语义核验；输入改动使旧证明无效；检查不移动或修卡。

责任模块：M06 代码双门禁。验收：E16、E17、E19。

### R10 最新代码只读合入检查

作为 committer，我需要受信规则固定 H/B/T/V 与逐 claim reused/inherited/revalidated 证明，在最新业务代码观察点二次核验并于合入前重核有效性。

失败路径与边界：源码/规则/head/基线/必要 ref 或事件变化使证明过期；依赖不全不能继承；CI 零改卡、锁、链接和业务代码，不 apply/commit/push/激活。

责任模块：M06 代码双门禁、M09 Skills/Workflow与部署验收。验收：E26、E27、E28。

### R11 渠道身份与不可变索引代次

作为消费者，我需要 local 正常使用未合入 stable，shared 仅使用实际合入且确认/证明匹配的内容；索引和正文属于不可变 generation，经完整自检后条件激活。

失败路径与边界：不混 local/shared，不从丢失证明反造通过；构建/激活失败继续旧完整代，manifest 不自摘要，Windows 不覆盖使用中数据库。

责任模块：M07 代次索引与消费。验收：E20、E22、E28、E30。

### R12 合格断言优先的可解释检索

作为查询用户，我需要授权/渠道/purpose/scope/当前有效性硬过滤后召回和 top-k，支持原样精确符号、v3 中英文词项及可追踪排序。

失败路径与边界：错 Target/阻断断言不贡献候选、词频、摘要；重复 span/拆 claim 不抬分，非连续片段不拼短语，不以降权替代硬阻断。

责任模块：M07 代次索引与消费。验收：E21、E22、E24。

### R13 同代精读与有据限域回答

作为查询用户，我需要精读固定代次正文、按定位回源并得到真实检索/读取收据，答案显示渠道、知识身份、claim、来源和实际证明/人工确认及缺口。

失败路径与边界：切 active 或改工作区不混读；仅 Host/设计文档不能推断全链路/实现/实测；无召回不证明无实现，未检索不伪造命中。

责任模块：M07 代次索引与消费、M01 契约与运行基础。验收：E22、E23、E24、E25。

### R14 当前失效阻断与双水位治理

作为维护者，我需要来源/宏/构建/pair 变更沿 source→claim 和 requires/derived_from 传播，先持久化事件/影响/阻断，再分别推进扫描与知识应用水位。

失败路径与边界：related_to 不默认全域传播；修订失败不丢阻断，重放幂等；回滚索引不撤销当前阻断；精读/回源/输出前复查授权与事件。

责任模块：M08 持续治理、M07 代次索引与消费。验收：E25、E29、E30。

### R15 可恢复编排与显式发布授权

作为使用者，我需要生产/治理 Workflow 以同一 operation、基线与 final-view 摘要交接，区分能力 Skill、编排、检查、合入和发布责任。

失败路径与边界：同名入口不遮蔽/递归；等待或返回修订核摘要，已 apply 不重复写；索引失败只恢复索引；无上库授权停在本地，CI 不隐式运行生产。

责任模块：M09 Skills/Workflow与部署验收、M05 人工确认与事务。验收：E11、E12、E14、E19、E27、E28。

### R16 授权边界与不可信材料

作为项目 owner，我需要源码、原件、卡、索引、缓存、证据和端点均受同域实际授权约束，记录脱敏且来源内指令不成为执行/发布授权。

失败路径与边界：不借其他组权限，不把目录/AGENTS/config 称 ACL；权限撤销中止未交付内容；参数不执行为 shell/SQL，凭据/私有路径不流入共享。

责任模块：M01 契约与运行基础、M02 项目发现绑定、M03 来源快照、M07 代次索引与消费、M08 持续治理、M09 Skills/Workflow与部署验收。验收：E04、E08、E09、E25、E27、E33。

### R17 受控发行与真实宿主部署

作为部署者，我需要固定框架/契约/工具来源和兼容版本，在实际 Windows/Agent 宿主安装全局入口和受托管薄规则，并验证新会话选择、绑定、加载轨迹。

失败路径与边界：不自动安装/升级/追踪 master；有条件复用须满足许可/声明要求，否则独立实现；CLI 启动或目录存在不等于完整链路或稳定触发。

责任模块：M09 Skills/Workflow与部署验收、M01 契约与运行基础、M02 项目发现绑定。验收：E06、E30、E32、E34。

### R18 可执行且分层的交付证据

作为验收者，我需要 E01–E34 的可重复输入、预期、实际与证据，分别汇报合成机制、宿主触发、六 Target/三 pair 真实业务及外部访问负测。

失败路径与边界：未执行、失败和通过分列；fixture 不冒充 WiFi 覆盖，协议不冒充成绩；不读取受限 gold，不把未来来源能力列首发已完成。

责任模块：M09 Skills/Workflow与部署验收。验收：E31、E32、E33、E34。


## 范围与排除项

以已批准详设为范围真源。首发仅 WiFi 六 Target/三 pair；文档仅 raw 已落地文件。远端链接、dbox 仓外映射、wiki 网页与 3ms、向量/FTS5、多领域、自动后台监控均延后。源码登记、业务语义和真实授权须据实验收。

项目本轮只实现 first-slice.md 中 T01/T02 的可运行基础；完整首发按 tasks.md 逐张交付。SDD 文件、合成卡与记录不是生产知识，不自动进入 knowledge/。

## 追踪方式

`traceability.json` 逐项保存 R01–R18 → M01–M09 → 149 路径 → E01–E34 → T01–T28；每条验收保持 planned/partial/verified/external_validation_required 等实际状态。3 条未来 sources 路径为 deferred，X/D/R 类型通过登记或生成实现，不手工制造来源或业务事实。
