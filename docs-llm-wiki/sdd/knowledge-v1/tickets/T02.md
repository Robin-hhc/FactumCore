# T02 仓外路径 resolve_project 与显式入口读取首切片

- Module：M02/M01。Blocked by：T01。需求：R03、R16、R18 的确定性程序切片。E：E05、E07、E08 的适用合成程序场景；不包括 E06 宿主隐式触发。
- 具体文件：`S/workspace.py,receipts.py,cli.py`；`S/tests/test_workspace.py`；合成公共 `W/config.yml`、只供读取的用户级 registry 及合成入口文件。`config.local.yml` 接入、全局 Skill 与用户规则安装不在首批文件范围。
- 行为：实际程序接口为 `resolve_project(..., load_context=False)`；CLI 为 `project resolve --path <path> --registry <registry> [--base <base>] [--load-context] [--authorization-epoch <epoch>]`。按明确任务路径/基准、真实路径/checkout 身份和有限登记定位知识根；默认返回 resolved 与入口清单；显式 load_context 开关执行入口字节读取，返回包含内容、摘要及 read_bytes trace 的 `entry_reads`，才可将程序收据记为 context_loaded。对配置/入口/checkout/授权 epoch 变化返回新的可比较绑定指纹；不能把一个来源/日志里任意出现的路径当作用户切仓请求。
- 边界：context_loaded 仅说明此程序实际读取并输出了入口字节，不证明模型已采纳这些规则，也不证明宿主会隐式调用 Skill。本轮不接私有覆盖、不安装全局 Skill/用户薄规则、不跑 bootstrap/自动摄入；不得整盘扫描、改登记真源/知识正文或利用旧缓存冒充新读取。缺登记、歧义和入口不可读取均有明确诊断，不虚构知识关联。
- 可执行验收：`python -m pytest S/tests/test_workspace.py`；公共 project CLI 从不同临时 cwd 对中文/空格路径解析到同一精确 checkout/领域，前缀相似路径不误配，同名 clone/worktree 可区分。不开开关时无入口正文读取且状态 resolved；打开开关才返回可核对原字节的内容/摘要/entry_reads，入口失败不报 context_loaded；配置/入口/授权 epoch 改变使绑定指纹变化。输入/正文不改，无网络、无整盘扫描。此结果不关闭宿主触发 E06、私有覆盖部署或模型采纳验证。
