现行名称和目录以架构设计 §5.3 为准，用户后续明确决定优先。唯一领域根为 `himate-knowledge-wifi-mp/`；项目根 `skills/common/knowledge/`、`workflows/common/knowledge/` 仅表示开发分发源码。实际能力在 Agent 自己的目录，首次部署统一使用分发仓根的 `deploy.ps1`；explore 负责路由与只读项目发现，旧 setup 仅供显式诊断或兼容，日常由 harness 调用。节点不要求 catalog 或流程登记，业务运行不依赖项目根能力源码。项目根统一以 `repo/` 示意，Git 在项目根执行；知识根和能力目录不建立嵌套 `.git`，业务代码保留项目实际多目录结构。

目录图采用默认布局，实际知识根按根 `config.yml` 的 `knowledge_roots.wifi` 解析，允许安全嵌套；项目配置由用户在这份文件维护。根 `AGENTS.md` 由业务仓维护代码架构与开发约定，本开发仓仅本地保存；分发 `AGENTS.md.example` 供合并四项位置说明和 explore 入口指针，不覆盖业务仓已有文件。全库能力介绍和路由归 `hs-knowledge-explore`；部署操作见[首次环境安装](使用说明.md#2-首次环境安装)，已有部署与上下文时直接调用业务能力，缺少入口时才做只读发现。目标代码仓在远端时，先由用户或部署维护者在 OpenFlow 配置、启用并验证 SSH MCP，连接凭据留在宿主；具体见[远端执行准备](使用说明.md#12-远端执行先配置-openflow-ssh-mcp)。Agent 通过该能力执行脚本与仓库操作，核对执行端原生项目路径、已有全局 Python 和配套已安装 Skill，不将调用端路径当成远端路径。同机执行不要求 SSH。缺执行能力时先报告并讨论方案，不自建 runner 或工具副本。产物沿用 K 的 `.build/`、`logs/`、`artifacts/`，操作集中见[使用说明](使用说明.md)。

项目配置以 `code_root` 和 `modules` 的相对路径、芯片、端、特性及用途说明架构；不要求手填绝对代码根、六 Target／三 pair 或重复授权。新配置按模块范围读取实际文件并固定内容指纹；版本仅采用有出处的材料，未知不阻断当前文件静态核验。目录标签不替代宏、构建或协议事实。使用说明讲填法和调用，详细设计第 5 章讲节点文件设计，知识库关键点说明跨领域适配，并集中维护路径与核验边界；历史配置与验证记录按原版本解释。

架构设计解释分层与协作；详细设计分概要和节点设计两层，以流程图、分支条件和文件职责表达。设计正文不记开发轮次、票据状态、Agent 工作进度或历史测试成绩；这些进入 SDD 工件。系统设计不构成正式领域事实，Schema/Contract 机器规则归 `../governance/`，此处不另建执行契约。

能力说明以实际八包和两个Workflow为准：explore、source、change-plan、view-materialize、lint、apply、query、maintain，均加 `hs-knowledge-` 前缀。ingest保留P1扫描、P2备料、P3内容决策、P4完整稿、P5独立审阅和质量检查、P6转写记录、P7安全落位及检索收尾七个业务步骤，由六个节点调度。首节点`prepare_sources`由source默认`run`同进程完成P1/P2；P6仍用source.record，P5用lint.review，P7用apply.batch。P5由独立reviewer执行，其余节点为coder。维护图表时区分业务步骤与调度节点，不将独立动作或内部检查新增为必走节点；节点文件分工见详细设计第5章。

新启动ingest使用新操作，source默认`run`从当前输入、正式处理记录和维护限制生成清单，有待办再备料；仅完整且没有待办、维护限制、缺口或明确目标时返回`unchanged`，缺失／读失败／不完整扫描不能当无变化。扫描事实由脚本生成，Agent只传范围或目标并消费确切引用，不重写文件清单、指纹、变化分类或完整性。独立`scan`只观察，`prepare`可按固定扫描单元或明确目标备料。P3／P4／P5缺料回首节点时明确调用`prepare`，携旧材料、前序稿及理由，不执行默认扫描；缺口可保存后交P3决定处置。采用输入漂移按原文、旧卡、代码、配置或规则分别刷新，不能将`affected_scope`诊断路径全当raw的`source`参数，也不无限自动刷新。P3—P7业务保持，运行故障留当前节点；返工保存新版本不覆盖旧工件，只有明确继续某次执行才沿确切引用核对停点。

固定脚本检查实际材料、逐Claim理由和确切内容绑定，不认证作者身份或代替内容判断。角色、上下文隔离与执行顺序由宿主／人工测试者落实，Skill不要求Workflow身份、catalog或上游通过票据。未知Target、版本、构建条件保持unknown；静态源码结论不统一要求编译产物，编译／运行／实测断言须有实际材料。Skill内部通过受锁公共函数复用领域规则，不委派兄弟CLI或导入兄弟私有脚本；迁移后的说明和源码链接指向当前公开动作或公共实现，不再将已退役包列作运行依赖。

P1—P6在知识根内产生的本批新材料、稿件、证据、代码核验副本、事件拟稿和请求／输出都放在本批暂存目录，正式卡、导航、来源锁、事件及索引不变；P6只机械转写待发布记录。P7.batch重核输入快照、写删集合、原版本和实际落盘字节，不重跑P5质量判断。内容与必要依据发布并核验后，保存正式成功处理记录及适用事件，再完成真实索引、预定查询、同代精读和原基线激活，最后清理本批可删暂存；整批完成须同时满足适用检索和清理要求。仅记录批保留处理结果及欠账，不新建或启用索引。旧apply.run及其恢复保持原事务语义；独立索引、回归、恢复和提交核对仍由apply提供。

正式来源、处理记录和发布结果用于共享与后续消费，执行暂存和事务备份用于本机交接，文档须分开说明。新正式结果位于 `logs/publications/<操作>/`，必要依据位于 `logs/evidence/published/`；清理后正常扫描、检查、查询、回源和提交核对不依赖生产者的旧暂存。指定操作的status优先读取正式发布与完成结果，只说明已保存的执行事实；当前规则、来源和索引资格须由相应检查另核。无目标status是明确的全局历史查看，不能据它替新流程选择旧稿。

用户可随时退回或入库后新建修订，输入变化须重新取得材料。已发布内容只补实际缺失的检索收尾或清理，不重复写入；清理失败保留发布成功事实，报告未完成，不回滚内容。清理仅限本批明确可删文件，借用、保护或用途不明项保留并说明，不删除其他操作、正式依据、活动索引或稳定写锁，不要求 `.build/` 全空。Git提交、固定CI与合入是人工后续，提交核对只读真实Git对象与变更范围。保留旧正式引用、历史工件原字节和旧操作事实，不批量迁移或重签。

独立lint Skill默认formal/full，CI复用L1—L5固定函数而不调用Agent。巡检 Workflow 先独立同步，再用脚本比较上次成功基线、raw 清单和登记代码文件，按实际待办复用 source.prepare 与 ingest P3—P7；无内容问题直接核验结束，仅索引问题维护派生索引。实际处理、查询、激活与清理完成后才以 CAS 推进本地成功基线，欠账和失败保留。外部系统负责周期触发，不嵌套 Workflow；旧 lint Skill 的默认 formal/full 与独立 audit-references 继续可用。maintain默认仍为inspect-context；query只消费活动代。巡检观察保存在本机logs/patrol，成功状态在.build/runtime，不随Git共享。P7未完成沿确切原操作续办，不重复apply；无法自动处理的基础登记损坏保留阻断。设计、合成测试和真实宿主/内部MM适配验收分别表述，测试记录进入SDD。

实现修改前核对共享设计、源码与现有测试；本地有对应 SDD 需求、设计、任务和测试计划时一并参考，依据实际验证更新本地记录。保留历史工件原字节，不批量替换旧记录路径或状态，不把本地开发工件重新加入 Git。普通文档整理不读受限 gold。文档独立内容复核、本地代码只读核验与固定 CI、六类原件及未知业务上下文遵循上级 AGENTS。

不新增 research、experiments、agents、superpowers 或设计文档子目录。系统设计优先维护架构与详细设计两份主文档，路径与部署约定集中维护在知识库关键点；操作写使用说明，任务、测试、发布与历史记录写相应 SDD 工件。

暂存、正式发布、续办与保存边界集中见[详细设计 §5.7](知识库详细设计.md#57-p7安全事务真实索引与检索收尾)、[§6.3](知识库详细设计.md#63-命令分派与工作流续办)和[§6.4](知识库详细设计.md#64-哪些内容上库哪些用于本机执行)。共享入口只链接共享文档；本地SDD和早期讨论归档不作为部署或日常操作前置。未完成批次暂存的全局回收和罕见P7部分写入的自动修复不在当前保证内，不增设常规maintain清理节点。独立lint可写自己的报告，独立maintain保留明确授权的业务写入，两者不清理其他任务的暂存。
