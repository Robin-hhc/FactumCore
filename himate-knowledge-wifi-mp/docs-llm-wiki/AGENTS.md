现行名称和目录以架构设计 §5.3 为准，用户后续明确决定优先。唯一领域根为 `himate-knowledge-wifi-mp/`；项目根 `skills/common/knowledge/`、`workflows/common/knowledge/` 仅表示开发分发源码。实际能力在 Agent 自己的目录，首次使用其 `hs-knowledge-explore/scripts/setup.py` 检查现有全局依赖并读取项目配置，日常由 harness 调用。节点不要求 catalog 或流程登记，业务运行不依赖项目根能力源码。项目根统一以 `repo/` 示意，Git 在项目根执行；知识根和能力目录不建立嵌套 `.git`，业务代码保留项目实际多目录结构。

目录图采用默认布局，实际知识根按根 `config.yml` 的 `knowledge_roots.wifi` 解析，允许安全嵌套；项目配置由用户在这份文件维护。`hs-knowledge-explore` 首次准备全局依赖，后续定位项目并加载上下文。SSH 信息放该 Skill 的 `config.env`，harness 负责连接并核对执行端实际可调用的能力；入口提示不代表已上传脚本或已验证远端，不将调用端路径当成远端路径。缺执行能力时先报告并讨论方案，不自建 runner 或工具副本。产物沿用 K 的 `.build/`、`logs/`、`artifacts/`，操作集中见[使用说明](使用说明.md)。

项目配置以 `code_root` 和 `modules` 的相对路径、芯片、端、特性及用途说明架构；不要求手填绝对代码根、六 Target／三 pair 或重复授权。新配置按模块范围读取实际文件并固定内容指纹；版本仅采用有出处的材料，未知不阻断当前文件静态核验。目录标签不替代宏、构建或协议事实。使用说明讲填法和调用，详细设计第 5 章讲节点文件设计，知识库关键点讲共享映射和多仓文件核验；历史配置与验证记录按原版本解释。

架构设计解释分层与协作；详细设计分概要和节点设计两层，以流程图、分支条件和文件职责表达。设计正文不记开发轮次、票据状态、Agent 工作进度或历史测试成绩；这些进入 SDD 工件。系统设计不构成正式领域事实，Schema/Contract 机器规则归 `../governance/`，此处不另建执行契约。

统一约定：一条 ingest 完整串起 P1 扫描／续办、P2 材料、P3 阅读计划、P4 写稿、独立内容复核和适用代码语义核验、P5 调用 lint Skill、P6 登记处理记录、P7 本地入库、索引全验、目标查询与活动代激活，通过后 ingest 结束；仅记录批保存记录后结束，不再分前后两段。详设 §3.1 展开 lint 的 L1—L5 只读检查；它可被 ingest、手动或定期调用，只检查和报告。输入未变且停点仍有效时续办原操作；退回改稿或输入变化后建立新操作和新视图，重新完成独立复核与固定检查。原件未变的用户修卡请求仍进入 P2，显式选取相关单元与已有卡，不按无变化跳过。Git 提交、触发 CI 和合入均是人工后续流程，不属于 ingest 的完成条件。C1 直接复用 lint 的已有固定脚本和确定性函数，通过后由人合入，不调用 Agent，不另开发业务构建任务。源码分析按确切源码和逐 Claim 条件核验，不统一强制编译产物；具体产品当前实现核对真实 Target 和条件；编译、运行或实测断言须对应证据。本地原件核对确切捕获对象，不要求先有 Git 提交；跨机恢复与 CI 输入由人工上库时准备。P2 保留的旧卡正文与指纹作为历史检查输入交给 lint 和 P7；索引回归沿用构建返回的代次及活动指针基线，激活成功才报告完成。索引构建不另拆维护、激活或发布交接主线；现有模板与实际调用边界仍按使用说明和源码核实。

独立内容复核的角色、上下文隔离与执行顺序由人工测试者或 OpenFlow 安排；Skill 只校验本次业务记录、逐 Claim 理由、引用和确切视图／源码绑定，不要求作者链、Workflow 身份或上游通过票据。apply 保留实际固定检查及安全写入，不自动生成 supported 验收摘要；索引和查询按实际来源、工作树源码、配置范围及采用的构建／运行材料核验，`code_contexts` 是生成的业务数据。显式签名发布回执仍核身份真实性，共享索引构建的 `knowledge_commit` 只核仓库快照，不代表 CI 或复核通过。用户修订以新视图记录，历史原字节保留。

实现修改前核对共享设计、源码与现有测试；本地有对应 SDD 需求、设计、任务和测试计划时一并参考，依据实际验证更新本地记录。保留历史工件原字节，不批量替换旧记录路径或状态，不把本地开发工件重新加入 Git。普通文档整理不读受限 gold。文档独立内容复核、本地代码只读核验与固定 CI、五类原件及未知业务上下文遵循上级 AGENTS。

不新增 research、experiments、agents、superpowers 或设计文档子目录。系统设计优先维护架构与详细设计两份主文档，路径与部署约定集中维护在知识库关键点；操作写使用说明，任务、测试、发布与历史记录写相应 SDD 工件。
