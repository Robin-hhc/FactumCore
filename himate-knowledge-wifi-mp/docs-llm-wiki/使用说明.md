# HiMate 使用说明

默认已把 `himate-knowledge-wifi-mp/`、`AGENTS.md.example` 和 `config.yml` 放入真实代码仓，后两个文件位于仓根；配套 Skill 已安装到 Agent 自己的目录。接入时保留业务仓已有的 `AGENTS.md`，仅合并示例中的 `main/`、`config.yml`、知识根及设计文档四项说明和 `hs-knowledge-explore` 入口指针，不覆盖原有业务内容。没有 `AGENTS.md` 时才将示例改名为该文件，并按真实业务仓补全；未知部分保留大纲与 `...`。本开发仓的根 `AGENTS.md` 仅本地维护，分发文件为 `AGENTS.md.example`。

使用顺序：**配置连接信息 → 按需首次准备 → ingest → lint → query**。知识库统一入口为已安装的 `hs-knowledge-explore`；入库通过 OpenFlow 执行 Workflow，独立检查和查询通过 Agent 调用对应 Skill。已有知识可直接查询；手动或周期检查代码引用变化时，另行启动只读 lint 巡检 Workflow。

<a id="配置项目代码架构"></a>

## 1. 两个配置文件

| 文件 | 位置与用途 |
|---|---|
| `config.env` | 位于 Agent 已安装的 `hs-knowledge-explore/` 内，保存本机 SSH 连接配置和服务器代码仓位置，由 Windows 用户配置，不上库。 |
| `config.yml` | 位于实际代码仓根目录，由项目维护者手工维护并上库，使用者沿用仓内配置。 |

Windows 用户先找到已安装的 `hs-knowledge-explore/` 文件夹，将其中的 `config.env.example` 复制为同目录的 `config.env`，再按模板注释填写：

| 配置项 | 填写内容 |
|---|---|
| `EXECUTION_MODE` | 代码仓在服务器上时填写 `ssh`。 |
| `REMOTE_PROJECT_ROOT` | 服务器上的实际代码仓根路径，该目录应包含业务仓 `AGENTS.md` 和 `config.yml`；填写服务器原生路径。 |
| `SSH_HOST`、`SSH_USER`、`SSH_PORT` | 服务器地址或已有 SSH 别名、登录账号和端口；账号可沿用已有 SSH 设置，默认端口为 `22`。 |
| `SSH_IDENTITY_FILE` | Windows 本机已有私钥文件的路径；已有认证可沿用时可留空。 |
| `PYTHON` | 服务器现有全局 Python 的命令或路径。 |

`config.env` 位于 Agent 的能力目录，不放到代码仓中。代码仓与 Agent 在同一台机器时，将 `EXECUTION_MODE` 设为 `local`，由 Agent 在当前代码仓执行，无需填写 SSH 参数。

<a id="首次准备运行依赖"></a>

## 2. 首次环境安装

真实根 `AGENTS.md` 已按业务仓维护、配置完成且首次需要准备环境时，发给 Agent：

```text
请使用 hs-knowledge-explore 完成当前知识库的首次环境准备。
读取本 Skill 的 config.env（存在时），按配置进入项目；同机时使用当前代码仓。
读取项目根 AGENTS.md、config.yml 和知识根入口，
在项目所在机器使用已有全局 Python 运行本 Skill 的 setup.py，按需安装缺失依赖。
最后报告项目位置和安装结果；遇到缺项时说明具体原因。
```

setup 只检查依赖和项目配置，不自动复制、改名或合并示例；只读发现读取真实根及领域 `AGENTS.md`，不会以 `.example` 代替。此后按 explore 指引直接使用下面三个日常任务；新会话找不到项目时才调用只读发现，不需要重复安装。

<a id="1-三个常用命令"></a>

## 3. 日常使用

| 顺序 | 任务 | 类型与使用方式 |
|---|---|---|
| 1 | `ingest` | Workflow：通过 OpenFlow 运行 `hs-knowledge-ingest`，完成原件入库、更新或已有知识修订。 |
| 2 | `lint` | Skill：向 Agent 提出检查要求，并指定 `hs-knowledge-lint`，获得只读检查报告。 |
| 3 | `query` | Skill：向 Agent 提问，并指定 `hs-knowledge-query`，完成知识检索和分析。 |

巡检正式知识的来源／代码引用时，在 OpenFlow 中选择同名 `hs-knowledge-lint` **Workflow**；它与上述 lint **Skill** 分属 Workflow／Skill 目录，不改变原 Skill 的默认检查行为。

已有知识可直接 query；日常维护按 ingest、lint、query 的顺序检查更新结果。

<a id="2-加入文档后怎么入库"></a>

### ingest：通过 OpenFlow 执行入库 Workflow

1. 将原件放入知识根 `docs-raw/` 对应目录：`conventions/`（约定）、`chips/`（芯片）、`storys/`（需求）、`specs/`（规格与设计）、`protocols/`（协议）或 `troubleshooting/`（问题定位与排查经验）。
2. 确认 OpenFlow 已加载 `hs-knowledge-ingest` Workflow，配套 Skill 及 `coder`、`reviewer` 角色已接入，然后在 OpenFlow 中选择并运行该 Workflow。
3. 查看 Workflow 返回的处理范围、知识更新、检查与查询结果。未完成时按实际停点和材料缺口续办。

日常入库统一通过 OpenFlow 运行，由 Workflow 编排扫描、生产、独立复核、检查及本地入库。Workflow 内已经包含 lint、索引验证和目标查询；内容批完成后，可再独立 lint 或 query 复查结果。

普通公开子调用上限为 2 分钟，包括来源恢复、单卡读取、计划核验、视图构造及候选检查／修订；搜索单独为 5 分钟，整批查询回归为 20 分钟。这些是单个子进程的等待上限，不是日常响应耗时目标；宿主的整体限时另须覆盖相应调用及回归累计耗时，具体见[运行与续办约束](知识库详细设计.md#63-命令分派与工作流续办)。遇到 `SIBLING_TIMEOUT` 表示运行未完成，先检查原操作进度、事务和活动代，再从实际停点续办；卡片已落位而检索收尾超时时，不重复 apply，也不为消除超时反复改稿。

只处理部分材料时，向 Workflow 提供来源范围，例如 `docs-raw/troubleshooting/`；修订已有知识时，提供目标卡片和修改要求，原件未变也可修订。问题定位经验可按模块建立子目录，材料宜写清现象、环境与触发条件、排查过程、根因或当前判断、解决方法和验证结果，保留未解决、未验证部分。

ingest 完成本地知识更新；Git 提交和上库由人后续处理。

<a id="4-怎么单独检查"></a>

### lint：使用 Skill 独立检查

向 Agent 提出检查要求，同时选择或注明 `hs-knowledge-lint` Skill。例如：**“使用 hs-knowledge-lint 检查当前知识库。”** 需要限定范围时，一并说明。

Agent 返回检查结果和问题位置。lint 只检查和报告；需要修复时，将问题交回 OpenFlow 的 ingest Workflow 修订后再检查。

需要检查“源码变了而知识未更新”等情况时，确认实际执行端已安装配套 Skill、OpenFlow 已加载 `hs-knowledge-lint` Workflow，再运行该 Workflow。它只有两步：先以原 lint Skill 默认设置检查正式完整库，再显式调用 maintain 的只读 `audit-references`，生成 JSON／Markdown 巡检报告。报告列出受影响的卡／Claim、来源或代码文件、原定位、旧 hash 与当前 hash、差异及材料缺口，并区分历史／指导性用途。原报告有问题或材料不足时保留真实状态，不把“已出报告”当成“检查通过”。具体节点见[详细设计 §3.1](知识库详细设计.md#31-lint-的检查流程)。

周期执行由外部调度系统触发同一 Workflow，部署后需核实宿主加载、执行端路径与实际报告；知识库不另建 runner 或内置定时器。巡检只写报告，不改卡片、来源锁、事件／水位或活动索引。历史引用与当前代码不同不直接表示引用错误；需要修复时，将报告和明确的卡／Claim 修订要求交给 ingest，原件未变化也可修订。

<a id="3-怎么查询和追代码"></a>

### query：提问并使用 Skill 检索分析

向 Agent 提出问题，同时选择或注明 `hs-knowledge-query` Skill。例如：**“使用 hs-knowledge-query 分析：<你的问题>。”** 可补充目标芯片、版本或关注范围。

Agent 检索并精读相关知识；涉及具体实现时继续追查对应版本的实际源码，给出结论、依据位置和仍不确定的部分。已有材料不足时说明缺口，需要补充材料再通过 ingest 入库。
