# HiMate 使用说明

默认已把 `himate-knowledge-wifi-mp/`、`AGENTS.md` 和 `config.yml` 放入真实代码仓，后两个文件位于仓根；配套 Skill 已安装到 Agent 自己的目录。机器已有 Python，首次使用由 `hs-knowledge-explore` 补齐运行依赖。

使用顺序：**填写两个配置 → 发送首次安装 Prompt → 日常 query / ingest / lint**。下面的 Prompt 直接发给 Agent，不是终端命令。

<a id="配置项目代码架构"></a>

## 1. 填写两个配置文件

| 文件 | 怎么填写 |
|---|---|
| 已安装 `hs-knowledge-explore/config.env` | 将同目录的 `config.env.example` 复制为 `config.env`，按注释填写连接方式、服务器地址、端口、项目根和 Python。跨机器用 `ssh`；同机用 `local`，也可不创建此文件。账号和密钥路径可沿用已有 SSH 设置。 |
| 项目根 `config.yml` | 按文件注释填写知识根、代码根及真实模块。`code_root` 相对配置目录，模块 `path` 相对代码根；仅处理文档可保留 `modules: []`。其他字段先保持现值。 |

`config.env` 是本机连接配置，不提交；`config.yml` 是随项目维护的配置。无需再准备其他部署配置。

<a id="首次准备运行依赖"></a>

## 2. 首次环境安装

配置完成后，发给 Agent：

```text
请使用 hs-knowledge-explore 完成当前知识库的首次环境准备。
读取本 Skill 的 config.env（存在时），按配置进入项目；同机时使用当前代码仓。
读取项目根 AGENTS.md、config.yml 和知识根入口，
在项目所在机器使用已有全局 Python 运行本 Skill 的 setup.py，按需安装缺失依赖。
最后报告项目位置和安装结果；遇到缺项时说明具体原因。
```

此后直接使用下面三个日常任务。新会话找不到项目时，再调用 `hs-knowledge-explore` 定位即可；不需要重复安装。

<a id="1-三个常用命令"></a>

## 3. 日常使用

| 任务 | 用途 |
|---|---|
| `query` | 查询已有知识，按需继续追查实际代码 |
| `ingest` | 把新增、变化的原件入库，或修订已有知识 |
| `lint` | 独立检查知识库，输出问题报告 |

<a id="3-怎么查询和追代码"></a>

### query：查询知识与代码

```text
请使用 hs-knowledge-query 回答：<你的问题>。
按问题选择查询用途，检索并精读相关材料；涉及具体实现时继续读取对应的实际源码。
给出结论、依据位置，以及仍不确定的部分。
```

已有知识不足时，Agent 应说明资料缺口；需要补充材料时再使用 ingest。

<a id="2-加入文档后怎么入库"></a>

### ingest：入库、更新与修订

先把原件放入知识根 `docs-raw/` 对应目录：`conventions/`（约定）、`chips/`（芯片）、`storys/`（需求）、`specs/`（规格与设计）、`protocols/`（协议）或 `troubleshooting/`（问题定位与排查经验），再发送：

```text
请对当前知识库执行 ingest，从 hs-knowledge-source-scan 开始，
按项目入库流程逐个调用已安装的节点 Skill，处理新增、变化和待处理的原件。
完成材料准备、阅读计划、写稿、独立内容复核、适用的代码检查和完整 lint，
再保存处理记录、完成本地入库、索引构建、目标查询和活动代激活。
最后报告处理范围、知识卡与查询结果；未完成时说明实际停点和缺少的材料。
```

当前由 Agent 分步调用 Skill，不依赖 Workflow 引擎。只处理部分材料时，追加“本次范围：`docs-raw/specs/<文件名>`”；修改已有卡时，追加“请修订 `<卡片>`，要求：`<修改内容>`”，原件未变也可修订。

问题定位经验放在 `docs-raw/troubleshooting/`，可按模块或问题建立子目录。材料建议写清“问题现象 → 环境与触发条件 → 排查过程 → 根因或当前判断 → 解决方法 → 验证结果”；尚未解决、根因待证实或未完成验证时，保留当前进展和缺口。需要只处理这类材料时，追加“本次范围：`docs-raw/troubleshooting/`”。

ingest 完成本地知识更新；Git 提交和上库由人后续处理。

<a id="4-怎么单独检查"></a>

### lint：独立检查

```text
请使用 hs-knowledge-lint，对当前正式知识库做完整只读检查。
报告检查结果，并按文件、位置和原因列出问题，区分内容错误与材料不足。
```

lint 只检查和报告。需要修复时，再让 Agent 按报告通过 ingest 修订。
