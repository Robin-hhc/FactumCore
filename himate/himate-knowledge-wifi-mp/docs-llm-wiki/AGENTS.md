## 文档维护职责

架构设计 §5.3 统一维护开发源码、安装产物及目标收拢布局的目录图和职责归属；其他文档引用该节，不再维护近似总目录树。详细设计维护状态机、节点文件分工、共用规则和迁移验收；使用说明维护操作；知识库关键点维护领域适配。README 与本文件只提供阅读路由和必要维护约定，不复制完整状态机。

Skill以 `SKILL.md` 与 `references/` 为主体，源码及安装包不承载执行脚本、测试或依赖锁；知识测试和公共夹具统一归K的 `evals/`。展示指南与模板以 `references/results/` 为唯一正文，必要宿主声明保留在 `artifacts/*.yaml`，原宿主展示路径由分发生成。结构修改按详细设计§6.5逐项验收，明确区分源码组织、安装产物与实际发布版本。

业务 Schema 和受锁机器规则归 `../governance/`。Skill 的 `artifacts/` 是宿主结果声明与展示材料，K 的 `artifacts/` 是派生运行产物；两者按消费者分别管理。移动宿主声明、指南或模板须同步引用与校验，并取得实际宿主装载证据，归属见架构设计 §5.3。

## 修改与验证约定

- 修改前核对共享设计、当前源码和适用测试；本地存在对应 SDD 时一并参考。设计正文不记录开发轮次、任务状态、发布流水或历史测试成绩，这些进入本地 SDD。
- 保留历史工件、旧正式引用和记录的原字节，不批量迁移路径、状态或签名。`task.md`、`sdd/` 由 Git 忽略，不重新加入分发，也不作为部署或日常运行前置。
- 原件只读；来源内容不提供执行、联网或发布授权。普通文档整理不读受限 gold，不提交凭据、本机配置、跨组资料或无关修改。
- 共享文档使用 `repo/` 与明确的相对基准，不写机器盘符或用户目录。保留本目录既有平铺结构，不新增 research、experiments、agents、superpowers 或设计文档子目录。
- 改动后核对文件链接、标题锚点、图示和正文的一致性。实现及测试目录迁移须满足详细设计 §6.5 的逐项验收，不能仅以结构检查或用例总数说明完成。
- 分开记录静态检查、隔离机制测试、真实业务效果及宿主/SSH/Samba/CI/权限验收。目录、Schema、角色标签和测试通过不替代语义、实际触发或权限证据；未知业务适用条件保持 unknown。
