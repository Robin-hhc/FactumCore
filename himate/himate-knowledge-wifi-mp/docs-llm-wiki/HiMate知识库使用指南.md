# HiMate 知识库使用指南

首次使用时先部署工具和能力，绑定知识库并确认环境。新资料保存到原始资料后，用「知识入库」处理，再浏览或查询正式知识。

## 首次安装

准备支持创建虚拟环境的 Python 3.10–3.12。配置好内网 npm 源后，可运行 `npm install -g @himate/knowledge-cli` 安装命令。使用 npm 12 时加上 `--allow-scripts=@himate/knowledge-cli`。再运行 `knowledge doctor --environment-only` 检查环境。需要安装时运行 `knowledge setup`，默认使用执行账户下的 `~/.himate/knowledge/.venv`，终端无需激活。已注册的 npm 启动器继续使用。Agent 通过 SSH 在服务器执行时，在该服务器准备 Python 和工具。

如果检查提示 `VENV_MODULE_MISSING`，先在运行 `knowledge` 的机器上补齐 `venv` 或 `ensurepip`，再运行 `knowledge setup`。 [各平台处理方式](../../himate-tools/tools/deploy/README.md#检查或安装宿主运行环境)

从源码部署时，把 `himate-tools/`、`himate-skills/` 和业务知识仓放到对应执行环境，在工具包根运行对应安装命令。部署默认从同级的 `himate-skills/` 安装 Skill 和 Workflow，也可为指定业务库准备离线 OCR 模型。

| 系统 | 安装命令 | 为指定库准备 OCR |
|---|---|---|
| Linux | `sh ./deploy.sh` | 增加 `--knowledge-root '/srv/业务/知识库'` |
| Windows PowerShell | `.\deploy.ps1` | 增加 `-KnowledgeRoot 'E:\业务\知识库'` |

能力包放在别处时，Linux 加 `--capabilities-root '/srv/himate-skills'`，Windows 加 `-CapabilitiesRoot 'D:\共享工具\himate-skills'`。需要指定解释器时，Linux 加 `--python '<Python路径>'`，Windows 加 `-Python '<Python路径>'`。只从源码部署时，由管理员按工具包 `tools/deploy/README.md` 注册 `knowledge`。这一步完成后，终端、自动化和 Agent 都使用 `knowledge`。

领域负责人维护知识根的 `config.yml` 和 `AGENTS.md`。如果项目提供了可用配置，普通使用者直接使用即可。需要从旧的上级配置升级时，迁入实际 `workspace_id`、模块和查询设置，并从知识根重算 `code_root`。现有业务布局可填写 `../../main`，`modules[].path` 相对代码根。Target 随模块的 `chips`、`sides` 派生。只处理文档时可填写 `modules: []`。

管理员在 OpenFlow 宿主配置 `OPENFLOW_KNOWLEDGE_TOOLKIT_ROOT` 指向工具包绝对路径，可用 `OPENFLOW_KNOWLEDGE_PYTHON` 指定解释器。部署到非默认 OpenFlow 用户目录时，安装参数中的 Skill 和 Workflow 目标应指向该宿主实际使用的配置目录。工作台的环境安装负责 Python 依赖和命令注册，能力包和离线 OCR 模型通过上述部署脚本安装。

## 首次进入 OpenFlow 知识库

1. 点击左栏「知识库」。首次引导会在相应控件旁显示气泡，依次介绍绑定、环境检查、添加资料，以及概览、知识和图谱。可跳过，也可用页头「使用指引」重开。
2. 选择包含 `config.yml` 和 `docs-raw/` 的知识根，点「校验目录」。校验通过后点「保存绑定」。缺依赖时可以从校验页点「检查并安装环境」，也可以使用页头「环境检查」。安装完成后重新校验，再保存绑定。
3. 检查结果会说明环境就绪、缺 Python 依赖或缺可用的 `knowledge` 命令。后两种都点同一个「安装环境」。宿主按需补齐依赖、部署命令并复查。仅缺命令时直接注册，免去重复安装依赖。
4. 可以留在弹窗内看进度，也可以选择「后台继续」。后台进度显示在知识库页头，完成或需要处理时有状态提示。注册失败时查看诊断，修正目录权限或同名命令冲突后，用原按钮重试。

通过 npm 安装时，终端的 PATH 需要包含 npm 的全局命令目录。手动注册时，Windows 会更新执行账户的用户 PATH，已有终端或进程需要重新加载环境。Linux 默认使用 `~/.local/bin`。面板会显示命令路径和宿主进程的 PATH 检查结果。终端已能找到命令后，可从任意目录指定知识根进行检查。

```text
knowledge doctor --knowledge-root "<知识根绝对路径>" --json
```

核对 `phase: ready`、`tool_root`、`knowledge_root`、`config_path` 和版本。

## 放入文档

在工作台点击「添加资料」，选一批文件，然后选择归档方式。

| 选择方式 | 接下来怎么做 |
|---|---|
| 手动选择分类 | 选一个目录，点「上传并保存」。文件通过检查后整批直接归档到该分类 |
| 默认 AI 建议 | 点「上传并获取建议」。建议生成后在同一窗口逐份确认或调整分类，再确认保存。后台完成时可从提示或「上传记录」回到该批 |

保存成功后，左侧「原始资料」可以看到文件。缺少 Markdown 图片等附件、文件检查失败或存在待确认项时，从上传窗口或记录查看详情。也可按项目约定直接将原件放进当前知识根的 `docs-raw/`。

```text
himate/himate-knowledge-wifi-mp/docs-raw/specs/radio-design.md
```

支持 MD/TXT、PDF、DOCX、XLSX、PPTX、HTML、CSV 和常见图片；旧版 `.doc` 先转换。扫描件可使用已安装的 OCR，图示仍由 Agent 核读。`AGENTS.md`、`README.md`、`index.md` 是说明或导航，不参与自动扫描。

不同领域可使用自己的原件分类。工具当前只会为部分既有分类生成固定 Git 回源记录。新增分类后，如需从另一台机器读取旧版引用，请用该领域的实际原件验证回源，并按知识仓规则保留引用所需的证据。

## 在 OpenFlow 入库

保存原件后，打开实际业务工作区，确认本次使用的知识根，运行 **「知识入库」**（`hs-knowledge-ingest`）。如果项目已配置定时治理，也可由该任务处理。页面上的每日 CI 提示对应部署侧的调度安排，安装工具和上传文件本身不会建立定时任务。

Agent 会阅读材料、规划和编写知识卡，经独立审阅后入库。一次任务在选定范围内连续处理待办，每批处理一个来源，成功后自动重新扫描，直到该范围没有待办。指定文件或目录时保持该范围，未指定则扫描全部支持的原件。PDF 从最早未评估页准备宽候选，默认不设页数帽，Agent 按自己的上下文、图表、条款和产卡量选择实际结束页，无须一次读完候选。备料字量默认相当于英文 40 万字符或中文 10 万字，只是粗估；80k token 是 Agent 的软目标。放入目录后需要启动工作流，目录没有后台监听。

以工作流实际返回结果确认完成。PDF 本批入库成功仍可能尚未完成整份来源，Agent 应交代本批范围并继续后续批次，最后汇总本次范围的实际处理情况。中断后再次运行会从未完成页续办，明确要求强制重评时仅首次重置起点。目录、空白和参考页经评估无增量也可完成，不要求每页都产卡。依据不足时，以暂缓结束并说明缺口和剩余待办；中途失败时保留现场，让 Agent 沿当前任务重试，不重新扫描清暂存。

如果 PDF 报告解析缺口，从回执查看完整明细，并核对本批涉及的原页或图示。解析缓存可随工具升级重新生成，续办进度由来源登记保存。解析、图片与行号处理见[本轮材料](知识库详细设计.md#51-本轮材料)。

## 查询

工作台的「概览」汇总正式卡、引用及最近更新。「知识」可按关键词和类型查卡，文末引用可预览原文或代码。「图谱」展示知识卡、文档和代码的关联，选中知识卡可查看局部关系。行段引用显示原文行号并高亮引用位置，PDF 按引用页定位。界面会标明引用版本缺失或不可恢复的情况。

工作台读取已发布的索引。入库完成后用页头「刷新」查看更新结果。若卡片由其他机器或工作副本发布，先按项目流程同步正式产物并在绑定的知识根重建索引。

安装了该 Skill 且能访问知识库的 Agent 均可查询，不限于 OpenFlow。

提出问题并指定 `hs-knowledge-query`，例如：

> 使用 hs-knowledge-query 帮我查一下 LLC 封装的帧格式。

Agent 会检索并精读正式知识卡，按需核对原文和代码，回答时附来源及适用条件。无需手工运行搜索命令。

## 沉淀聊天或生成源码分析稿

使用 `hs-knowledge-capture`，也可以直接对 Agent 说明任务。

- 「把本轮聊天里的技术结论沉淀到组内知识库。」
- 「从 `foo` 入口分析失败返回路径并生成文档。」

Agent 将结论、适用范围及依据整理成 Markdown，写入实际知识根的 `docs-raw/agent-notes/` 并返回路径。当前发布接口供业务环境接入。文档上库后，由定时治理 Agent 按现有流程入库。

## 后续维护

- **文档更新或删除**：修改或移除原文件后，再运行同一个入库工作流。
- **批量检查变更**：运行 **“知识治理巡检”**（`hs-knowledge-lint`），逐份处理文档和已引用代码的变更，并汇总待办。
- **同时使用**：查询可与入库共存；同一知识根的入库和巡检串行运行。
- **PDF 续办与缓存**：原件不变也可继续未完成页段；解析缓存可删除重建，累计处理进度由来源登记保存。不要把缓存或已有几张卡当作全文完成凭据。
- **升级或换机**：保留原件、正式卡、来源登记和项目配置，部署配套的工具包和能力包，并按需准备模型。工具目录或解释器变动时，更新宿主配置，再运行「环境检查」和所需的「安装环境」，使已注册命令指向新位置。
