# HiMate 知识库使用说明

日常使用只需：部署一次，将文档放入知识库，在 OpenFlow 运行入库工作流，再通过 Query Skill 提问。

## 首次部署

维护者先把知识包放入 `repo/himate/himate-knowledge-wifi-mp/`，并准备已有的 Python 3.10—3.12。本文用 `repo/` 示意 manifest 工作区根，它不要求自身是 Git 仓；其下可放多个实际代码仓。

进入上述知识根，按系统运行一次部署入口：

| 系统 | 命令 | 默认解释器 |
|---|---|---|
| Linux | `sh ./deploy.sh` | `python3` |
| Windows PowerShell | `.\deploy.ps1` | `python` |

两个平台都会展示以下默认安装目录；每项敲回车采用默认值，也可输入自己的地址：

| 内容 | 默认目录 |
|---|---|
| OpenFlow Skill | `~/.openflow/config/skills` |
| CAC Skill | `~/.cac/skills` |
| OpenFlow Workflow | `~/.openflow/config/workflow-templates` |

脚本还会逐个询问已有项目入口是否覆盖，回车默认 `y`，输入 `n` 保留该文件。确认选择后安装运行依赖，删除本次同名旧包并复制新包，再将知识根的 `config.yml` 和 `AGENTS-code-root.md` 按选择复制为 `../../config.yml`、`../../AGENTS.md`；不存在时直接创建。其他包与源模板保留。

OpenFlow 从实际安装目录加载能力。解释器、自定义参数和项目入口说明见[部署与环境准备](运维与命令参考.md#部署与环境准备)。

运行依赖应安装在数据的实际执行端，并使用同一 Python 执行业务命令。数据在远端时，由维护者先准备远端代码、配置、Python 和 SSH 通路，详见[远端执行](运维与命令参考.md#远端执行先配置-openflow-ssh-mcp)。

## 放入文档

把需要蒸馏的原始文档放进当前知识根的 `docs-raw/`，例如：

```text
repo/himate/himate-knowledge-wifi-mp/docs-raw/specs/radio-design.md
```

支持 MD/TXT、PDF、DOCX、XLSX、PPTX、HTML、CSV 和常见图片；旧版 `.doc` 需先转换。优先放设计文档、Spec 等有价值的资料。`AGENTS.md`、`README.md`、`index.md` 作为说明或导航，不参与自动扫描。

默认读取文档中可提取的文字和图片。扫描件 OCR 需要维护者额外准备[本地 OCR 环境与模型](运维与命令参考.md#本地文档与-ocr-准备)，日常任务不会临时安装依赖或下载模型。

## 在 OpenFlow 入库

打开实际业务工作区，选择并运行 **“WiFi 知识入库”**（`hs-knowledge-ingest`）工作流。可以说明要处理的文档，例如：

> 将 docs-raw/specs/radio-design.md 入库，按文档内容整理知识卡并关联实际代码。

Agent 会选择变化文档、阅读材料、规划和编写知识卡，经过独立审阅后入库。用户无需手工维护来源 ID、索引或调用节点命令。

**每轮处理一个变化文件。** 多份文档可以继续运行入库工作流，或使用下文的巡检工作流逐份处理。放入文件后需要启动工作流，目录本身不提供后台监听。

以工作流返回的实际结果确认完成。成功后，正式知识卡即可供查询；必要依据不足时，Agent 会说明缺口并暂缓处理。中途失败时让 Agent 沿当前任务续办，保留临时材料，续办规则见[进度续办](运维与命令参考.md#进度续办和完成判断)。

## 在 OpenFlow 查询

直接提出问题并指定 `hs-knowledge-query` Skill，例如：

> 使用 hs-knowledge-query 帮我查一下 LLC 封装的帧格式。

Agent 会检索正式知识卡、精读正文，并按需回到原文或代码，回答时附来源和适用条件。无需用户输入关键词 JSON 或运行搜索命令。

一般提问是否自动选中该 Skill 由 OpenFlow 的技能发现与调用机制决定；显式指定 Skill 名称可以明确本次查询入口。

## 后续维护

- **文档更新或删除**：修改或移除原文件后，继续运行同一个入库工作流，由 Agent 决定如何修订关联卡。
- **批量检查变更**：运行 **“WiFi 知识治理巡检”**（`hs-knowledge-lint`），逐份处理文档和已引用代码的待办，再维护索引并汇总剩余事项。周期触发由使用环境配置。
- **查询与入库**：查询可与入库共存；同一知识根的入库和巡检串行运行。
- **升级或换机**：保留原件、知识卡、来源登记和项目配置，按[更新与清理边界](HiMate知识库架构设计.md#55-框架更新与目录清理)操作。

环境配置、dbox、OCR、手动命令和故障诊断集中在[运维与命令参考](运维与命令参考.md)。处理原理见[详细设计](知识库详细设计.md)，目录与数据归属见[架构设计](HiMate知识库架构设计.md#53-himate-knowledge目录架构)。
