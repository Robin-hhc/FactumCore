# 卡片生命周期与六决策

`stable` 表示卡片未整卡退役，`deprecated` 表示整卡职责失效；缺省按未退役使用。状态不表示通用适用、实现或测量已验证，也不代替 P1—P5 进度。只有正式 `knowledge/` 中的卡参与检索；旧 `draft` 不自动改写或升为 stable，不进入默认搜索，可直接按 ID 阅读。显式退役卡默认不搜，可用 `include_deprecated` 包含，也可直接阅读。

| 决策 | ID、状态与知识去向 |
|---|---|
| create | 查重后新建独立主题与 ID，新卡写 `stable` |
| update | 融合同主题的新旧有效知识，沿用 ID、原路径和原 lifecycle；状态变化须 P2 明确决定 |
| merge | 保留主卡 ID，融合有效知识和引用；退出使用的旧卡退役并写替代链接，或明确删除并修复入链 |
| split | 明确各主题、来源和旧结论去向；职责连续的主题可保留原 ID，否则旧卡退役并链接新卡 |
| deprecate | 仅整卡职责失效时写 `deprecated`，正文保留原因、历史适用范围及可用替代入口 |
| defer | 必要依据不足，保留缺口与待办，不改正式卡或推进成功 hash |

局部结论过时只改对应正文；设计参考、旧 guidance/historical 声明或来源删除都不自动使整卡退役。修订退役卡的错字、定位和链接仍保留 deprecated；恢复使用必须由 P2 明确决定，再经过同一 P3/P4/P5，不新增卡动作或节点。旧 draft 需进入新候选时，也须 P2 明确决定采用新格式支持的状态，不能因读取或普通更新自动升级。

完整阅读后无增量，plan 写 `cards: []` 并说明不改理由；经 P4 审阅后 P5 登记来源已处理。这是文件处理结果，不是第七种卡动作。

P2 固定候选 ID/正式路径；P3 镜像路径写完整稿与明确删除清单；P4 先脚本核对再独立审阅；P5 直接复制并更新关系、索引和触发文件成功 hash，不重跑质量检查。改稿后重新经过 P4，P5 失败保留暂存并直接重试。Git 提交、推送和合入是后续独立动作。旧卡和历史记录不因读卡或索引重建而重写。
