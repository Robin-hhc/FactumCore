# 来源处理事实与运行记录

## 需要保留的事实

程序在正式来源登记中保存来源ID到实际路径的映射、文件存在性、上次完整成功处理的SHA-256以及必要时间/来源Git定位。卡片保存引用事实，数据库提供双向查询；已有卡引用不能代表整份文件处理完成。

存在的 raw PDF 可以分批处理，对应 resource 仅增加可选组：

```yaml
processing:
  source_sha256: <本次原PDF的SHA-256>
  reviewed_pages: [[1, 42], [79, 96]]
```

该组精确包含版本 hash 与累计物理页闭区间，不重复保存游标、完成计数或卡 ID。读写入口校验 hash、范围形状及严格正整数（不接受 bool），返回时规范化为排序合并区间；本轮检查和发布还按原 PDF 真正总页数核对边界。读查询不为规范化而改写来源文件。SQLite 查询结果按来源 ID 合并该正式事实，无需新增表列；重建数据库或删除解析缓存不丢累计覆盖。

reviewed_pages 仅记录范围内全部材料经评估、P4 审阅并完成本批发布或无卡登记的页；不是 Agent 打开过哪些页，也不是卡片证据引用页。原件版本不同不合并旧覆盖；来源删除清理失效 processing，并沿用删除完成语义。

来源或 PDF 本批范围完整审阅但无须产卡时，凭实际理由也可登记。PDF 部分完成只更新 processing，不推进上次整文成功字段；覆盖 1–N 后才登记完整成功 hash 并移除 processing。没有 processing 仍须比较当前原件 hash，不能默认全文已处理。显式 reprocess 首批前保留旧成功事实，首批成功后 processing 表示本次评估仍进行中，即使旧成功 hash 相同，也继续发现剩余页。defer、读取失败或未完成事项不推进范围或成功 hash。本次处理文档A，只推进A，不能因卡同时引用B和代码C就把B/C标成完成。

## 本轮交接

P1自动保存task和选中原件副本；PDF 同时交接 pdf_review 的起点、宽候选边界、字量及页索引，不默认限制页数。P2自主截断实际范围并写短plan.md，PDF 必须显式 source_pages；P3写完整cards及必要changes.json；P4写简短review.md，明确实际评估范围；P5只登记该范围，不把候选未读页或补读前文计入。当前批次暂存只在.build，下一轮P1可清空其内容并保留根README；可重建PDF解析缓存留在artifacts，正式进度留在来源登记。

P5先核对本轮 PDF 输入与范围的机械约束，再复制覆盖卡片、更新全部引用关系与检索索引，成功后保存本批覆盖或全文成功标记；不重复 P4 语义审阅。失败保留材料供当前session重试同一P5，不先回P1；重复登记按区间并集处理，不累计两遍。结果记录具体错误，不把失败当完成。

本批成功仍返回 phase completed，回执 source_complete 区分本批与全文完成。PDF partial 时 source_complete=false，包含 processing/remaining_pages；processed_hash 只反映实际最后全文成功值。入库 Workflow 可以结束本批并交付剩余范围，下次普通 scan 继续；巡检返回 L2 后仍将未完成 PDF 视为待办。

不增加前序通过票据、不可变视图链、CAS、应用层journal或备份链。数据库可用常规事务完成自身更新，不宣称外部文件与数据库在所有故障下原子完成。串行运行、Agent重试及必要时人工恢复是初期选择。

## 历史兼容

现有schema_version 2.0、operation、publication或completion等历史记录保留原字节供明确读取，不重签、不批量搬迁。它们不成为新单文件入库的前置；新流程也不继续生成旧阶段状态图。

运行摘要、格式或索引成功不认证Agent身份，不证明内容语义、代码适用条件或访问权限。P4独立审阅、固定检查和实际宿主验证分别说明范围。
