# 2.0 运行记录与业务校验

所有机器记录使用 schema_version 2.0、准确 record_kind 和规范对象摘要。节点记录绑定 operation、规则摘要、实际 Skill 包及运行依赖身份。摘要只检测内容和绑定变化，不认证执行者身份，不提供权限。

独立内容复核的角色和调用顺序由 OpenFlow 管理，人工测试可逐个调用 Skill。`content_review` 保存本次确切计划／最终视图指纹、审阅范围及问题清单；作者、复核者和上下文标签可作描述，不用名字证明角色隔离。文档的 `manual_document` 是保留的分类取值，不要求真人动作、宿主签名、展示 challenge 或确认记录。逐 Claim 依据、未解决问题和确切内容绑定继续校验；文档类不调用代码检查。

代码复核 Skill 检查逐 Claim 理由、证据、配置范围及实际源码字节。缺少当前结论实际需要的路径、配置或证据则保持 incomplete；历史／指导性源码结论允许未知 Target 和构建信息，但不得推广为具体产品当前适用或已编译运行。编译、运行或实测断言仍须有相应实际材料及指纹，材料变化后不能继续当作当前依据。检查不依赖作者链，不认证 Agent 身份或替代内容判断。

apply 自身针对实际拟写视图运行完整固定业务检查，保留来源恢复、代码引用、基线和安全写入校验，不要求 lint、复核或前驱 Skill 已通过的证明。可选输入的记录若与本次视图矛盾仍拒绝；可选复核材料后来删除不阻断按原视图／备份安全恢复。成功写入不自动生成 supported 或独立复核验收摘要。历史验收摘要保留其原始事实，不静默迁移或重签。纯记录批只保存实际处理记录，不授权知识内容写入。

用户可在流程中要求退回、暂缓或修订；稿件内容、来源、规则或相关基线变化后生成新操作并重新复核。已入库卡的后续修改走新操作，旧操作和处理记录保留。无回复不会制造用户同意，也不再是 ingest 的等待条件。缺少材料、内容复核失败或固定检查未通过仍保存真实停点。

事务 journal 记录完整 writes/deletes、expected-old／最终摘要、持久备份及每步结果。committed 重入返回原结果；非终态先受控恢复。发生外部新编辑时停止并保留现场，不覆盖编辑来完成恢复。索引和维护记录独立绑定代次、当前事件 epoch 及两水位，索引回滚不能撤销当前阻断。

新 ingest 的 P1—P5 只在 `.build/operations/<op>/` 保存本批材料、稿件、检查报告、待发布记录和归属清单。普通 scan 以正式处理记录和实际来源为准，不发现或恢复旧执行目录。新事务、备份和结果位于本批 `transaction/`，共用写锁位于 `.build/runtime/writer.lock`；旧事务仅在明确兼容／写安全检查中读取，不自动迁移。

P3 冻结 `publication_plan_digest`（含暂存映射）与 `content_digest`（确切业务内容，排除执行地址及 P6 后生成事实）。P6 内容及依据核验后才发布正式 ingest record 和不可变 `logs/publications/<op>/manifest.json`。`completion.json` 按 CAS 保存实际索引／冻结查询／激活和限定清理进度；`published=true` 与 `batch_complete=true` 分别表达发布和整批收尾。清理失败为 `cleanup_pending`，重入只补清理，保持已经发布的事实；未声明、借用或受保护文件保留并列原因。不得将执行完成记录解释为所有 defer／failed／uncovered 欠账已解决。

索引和查询不要求 apply／复核的上游通过证明。当前源码及模块／Target 范围直接按实际配置核验；已采用构建／运行材料时按其实际业务指纹复查，不以流程票据代替。

直接指定 Git knowledge_commit 时只核对实际仓库快照内容，不推断发布者身份或 CI 已通过。显式提供发布签名回执时，发布身份与受信签名仍须核验；这是发布数据真实性，不是上游 Skill 交棒证明。普通本地运行不需要发布回执、签名或 catalog 登记。真实宿主 Workflow 触发、六 Target、CI 合入与权限部署各有独立验收；Schema、包测试或合成数据不能代替。
