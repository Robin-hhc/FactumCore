# Raw 来源捕获契约（T03）

`source_id` 标识逻辑资料；`snapshot_id` 固定实际原始字节、声明版本与提取身份。主件及显式附件分别登记资源和快照，附件变化改变证据包身份。未知版本写 `unknown`，不推断代码 HEAD。

`hs-knowledge-source` 的 `prepare`／`capture` 读取六类仓内 raw，以及 `docs-raw/sources/dbox/<目录内相对路径>` 所指的本机资料。后者由实际知识根的 `docs-raw/sources/dbox.local.yml` 映射，配置仅含字符串 `schema_version: '1.0'` 和执行端原生绝对目录 `path`；模板 `dbox.example.yml` 与同目录精确 ignore 上库，local 配置不分发、不发布。`configure` 显式检查或修改该固定配置，根目录可读才报告来源就绪；Windows 文件部署与服务器实际配置分别报告。配置动作不扫描资料，不写正式来源锁或处理记录，也不注册为 ingest owned。

默认新全量扫描包含六类仓内 raw 与 dbox；显式限定原六类范围时不依赖无关 dbox。dbox 缺配置、根不可达或子树读取失败不能当无变化或推断整个目录删除。递归仅遍历普通目录和文件，拒绝配置路径、目录根及子级原生链接/junction、越界和大小写别名；配置根不得包含知识根。主件与相对附件均限于同一 dbox 根，附件可在根内回退。模板、local 和预留槽不作为资料；不跟随内容中的网页外链，不自动下载。

每个输入读取及完成前复查实际路径和内容；dbox 同时复核本批保存的配置与目录身份，同字节换目录也属于输入漂移。目录绑定仅用于本批执行，不进入共享 config_digest、source_id 或 snapshot_id；不同物理根的相同逻辑相对路径仍标识同一来源。格式提取由配套锁定适配器决定，不支持的格式明确报告缺口，不执行原件。二进制附件不作文本提取承诺。

`resolve-source` 按明确 `bundle_ref`／`source_ref` 校验对象、提取文本、locator 和资源／快照一致性。即使原件已移走，仍须返回被固定的旧字节证据；不可得时报告缺口。摘要证明内容一致性，不认证发布者；权限由外部部署承担。

新 ingest 的原件、提取和定位只暂存于 `.build/operations/<op>/`。bundle 的 `staged_objects` 显式绑定 `stage_ref`、`final_ref`、`kind`、`sha256`、`bytes`、`owner_operation_id`；来源声明预先使用正式地址。P1—P5 解析只采用本次明确映射，不发现其他操作的暂存。每个文本 locator 保留原字节与提取字符／行区间，原始 BOM／换行不因提取而改写。

P6 按冻结发布计划将必要原件、旧卡、提取及定位原样发布到 `logs/evidence/published/{objects,cards,extractions,locators}/`，核验后保存正式处理记录和 `logs/publications/<op>/` 发布闭包；正常消费与提交不得依赖随后清理的 stage。新捕获只产生冻结的来源变化提案，不提前登记正式维护事件。内容批发布来源锁后，P6 按原 old→new 转换登记事件；仅记录批不登记未被正式来源锁接纳的版本。

捕获不修改 `governance/sources.lock.yaml`、knowledge 或导航；它不证明来源语义正确。来源锁由明确 ChangeSet 经独立内容复核和固定检查后事务落位。

正式来源的跨机恢复不依赖生产机的 `.build/` 或证据缓存。配套 `hs-knowledge-source` 及公共来源函数的来源解析优先核验固定恢复对象；对象缺失时，只能使用正式来源锁中唯一登记的资源位置，并核对原始字节摘要和大小。raw／附件限定在六类仓内原件或上述 dbox 逻辑根，代码文件只能从当前项目配置声明的模块取得；不得搜索同名文件、跟随链接或以新版替代缺失旧版。dbox 的采用版本按现有 published 对象保存，不沿虚拟逻辑路径搜索代码仓 Git 历史。当前映射不可用时仍可恢复确切正式旧证据，当前匹配保持 null；当前文件已变则为 false，不能用旧证据冒称当前有效。已登记的普通 raw／代码固定 Git 原文恢复仍只读本地确切对象，不联网补取。

普通仓内 raw 在 capture 时尚未提交并不妨碍随后随正式资产一起提交。当前文件升级或删除后，可从正式登记路径的本地 Git 历史核对最多 1000 个路径变更提交，按 SHA-256 和大小选取确切旧版；不搜索其他路径、不追随改名、不执行签名验证或联网补历史。历史缺失、浅克隆或搜索范围不足时报告缺口，不重签历史锁或以最新版本代替。dbox 不镜像整个目录，必要原文字节随正式发布依据提交，私人配置和外部目录不进入提交／清理集合。

旧 `logs/evidence/{objects,checked-code,extractions,locators}/` 是本机缓存；新 `logs/evidence/published/` 是正式随仓依据，不能按缓存忽略或删除。旧声明的恢复路径缺失时，可按冻结 SHA 精确读取正式 published 对象，不搜索目录、不重签旧 snapshot。提取文本与定位图缺失时，从已核验的确切原版按配套适配器重建，结果仍须匹配原冻结指纹；不能复现或旧版不可得时报告未完成。显式构建／运行材料及有效限制状态继续按其原契约保全。

活动卡的每个代码来源须按[卡片规范](cards.md#代码来源的可选符号补充)填写 `code_ref`；缺失由公共固定检查报 `CODE_REF_REQUIRED`，不受 review_mode 限制。它补充该项的符号身份，不改变来源资源、快照、提取器或历史定位；历史记录、旧来源恢复和 deprecated 卡仍允许原四字段。P1 保留已有来源项并提供实际源码材料，作者在 P3 填写符号；捕获成功不会自动生成或批准一个符号引用。纯文档不强制连代码，但已登记代码来源不能用整文件或行段兜底绕过符号要求。

来源恢复分别报告旧证据与当前导航：先核确切快照和原 `locator`，声明 `code_ref` 时核其在旧证据中的绑定；再按当前配置和登记路径读取实际文件，返回 `code_navigation` 的状态、字节指纹及匹配位置。当前导航不以旧文件 hash 未变为前提，也不更新旧锁或旧定位。`current_source_matches` 的 true／false／null 保持原字节比较含义，导航状态不解除 current／implementation 结论原有的代码、配置、构建或运行限制。

公共解析由同一规则锁内的 `code_symbols.py` 和 `source_resources.py` 承担，检查不执行目标源码、Agent 或 CodeGraph MCP。同名条件定义、解析不支持和材料不可读均披露真实缺口，不猜活动分支；CodeGraph 仅供 Agent 辅助定位。来源范围仍限于登记路径，跨文件改名或搬迁须明确修订引用，不搜索同名文件替代固定原版。
