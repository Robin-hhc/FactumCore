# 生成组库分析稿

按本次工作区的 `AGENTS.md`、`config.yml` 确认实际项目、知识根和数据所在端。两类请求都使用[分析稿模板](references/analysis-note.md)。

1. **聊天沉淀**。从当前会话整理可独立阅读的技术结论、适用条件和实际用过的证据。保留重要例外及未核实边界。
2. **函数分析**。在实际模块内查找定义，用现有文件、调用上下文或 Target 消歧。读到足以解释指定问题的关键判断、分支与出口即止。只有入口或范围无法确定时才请用户补必要线索。
3. **落盘**。在实际知识根下按需创建 `docs-raw/agent-notes/`，写入一份完整的 UTF-8 Markdown。用技术主题命名，已有同名材料时选用不同文件名，保留原件。交付实际文件路径。治理流程后续按主题决定归卡和知识增量。

## 上库交接

预留宿主发布接口 `publish_note(project_root, note_path)`。`project_root` 是实际项目根，`note_path` 是该项目根下本次生成的 Markdown 相对路径。发布接口由业务环境接入，只接收这份文件。当前以写入文件为完成结果，回执标明「已落盘，发布接口未接入」。后续接入时以实际发布结果为准。定时治理 Agent 消费上库后的来源。
