# 分析稿模板

聊天沉淀与函数分析使用同一份 Markdown。章节按本次问题取舍，结论与证据保持就近对应。

```markdown
# <实际技术主题>

## 问题与范围

<要回答的问题、适用模块或版本。函数分析写明实际入口和分析到哪里。>

## 结论与依据

- <触发条件和可复用的结论>。依据：<实际文档章节、代码位置或验证记录>。
- <影响结果的分支或例外>。依据：<对应证据>。

## 未核实范围

<仅在影响适用性时说明缺口。>
```

- 聊天中用户确认的设计约束、静态代码观察和实测分别归因。保留实际使用过的卡 ID、原件和验证记录。关键实现结论写直接源码依据。
- 源码依据使用真实仓库相对路径、符号或行段和实际核实的版本。工作区内容无法绑定提交时说明观察范围，可记录实际文件摘要。未知宏、构建条件、跨端与运行行为保留为未知。
- 较复杂的流程可加图。保留能解释结论的关键入口、分支和出口，正文用短编号复用同一个依据时保持对应清楚。
