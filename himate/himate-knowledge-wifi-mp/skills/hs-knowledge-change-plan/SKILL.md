# 制定简短编辑计划

在实际知识根执行命令，Linux 使用 `sh ./knowledge.sh`，Windows 使用 `.\knowledge.cmd`；已注册入口可直接用 `knowledge`。位置由 Workflow 首节点确认，独立使用时从当前工作区 `AGENTS.md`、`config.yml` 获取。

## 阅读与决策

1. 先读 `.build/task.json` 和完整关联卡。PDF 先看 `page_index_ref`，按需分段读 `packet_ref`，结合自身上下文、图表、条款和产卡量选实际结束页；80k token 仅作软目标，不必一次读完宽候选。起点必须是 `start_page`，结束不超过 `end_page`。非 PDF 仍按全文评估，来源删除沿用原有判断；旧原文、其它来源和代码按需补读。
   完整评估选定页段内全部材料，目录、空白、参考等经核实无增量的页也纳入；不能只提炼其中某个主题。涉及图示的结论实际打开原图并结合 OCR 判断；复杂表格核对结构。完整 `source.parsed` 供必要补读，补读或卡片引用不自动扩大已评估范围。
2. 按知识主题确定卡片边界，不以来源文件或文件格式划分。决定哪些卡更新、哪些保持；同时检查本次文档新增的重要知识是否已有合适卡容纳，按主题、接口或实体做针对性查重。
3. 选择 `create/update/merge/split/deprecate/defer`。普通更新保留卡 ID 和原生命周期；状态变化和必要的标签调整在 P2 明确决定。局部过时只修对应结论；合并／拆分交代旧知识去向，依据不足明确缺口。
4. 将简短计划写入 `.build/plan.md`：开头用 YAML frontmatter 的 `cards: [{id, path}]` 固定本轮完整候选的 ID 和正式路径；`path` 相对知识根，采用 `knowledge/...md`。存在的 raw PDF 必填实际 `source_pages: [[start, end]]`，单个连续物理页区间，遵守 task 起点和候选结束上限；不默认将整个候选包计为完成。更新保留原路径，新卡按 `knowledge/index.md` 的现有类型导航选目录。只列本轮要产出完整候选的卡，未改卡不列，无产卡写 `cards: []`。
5. frontmatter 后用自然语言说明本文件主要主题，以及卡动作、结论怎么变、条件与依据、需要保留什么。旧卡结构中的有效条件、历史依据及关系须安排迁入对应正文，不能因简化而丢失；无须提前写完整正文或抄一遍所有未变结论。

本批 PDF 页段或非 PDF 全文完整评估后无增量，说明无需改卡或新增卡的理由，仍交后续审阅和处理登记。PDF 本批完成不等于整文完成；未覆盖部分由下一轮继续。仅某个旧主题无增量不足以结束本批，必要范围未读或依据仍有缺口时暂缓。

`task.source.kind=code` 时只判断本次代码对关联卡的结论及定位影响。包含代码分析的文档仍按本轮文档范围评估。

交 P3 的是计划路径和实际材料入口。计划决定变化时在 P2 同轮修订；不创建冻结版本、前序视图或通过票据。决策和计划格式见[六决策与短计划](references/request.md)。
