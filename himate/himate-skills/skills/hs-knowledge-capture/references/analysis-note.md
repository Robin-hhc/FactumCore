# 分析稿模板

会话总结与源码分析使用同一份 Markdown。章节按本次问题取舍，结论与证据保持就近对应；它是等待用户审阅的原稿。

```markdown
# <实际技术主题>

## 问题与范围

<要回答的问题、适用模块或版本。函数分析写明实际入口和分析到哪里。>

## 结论与依据

- <触发条件和可复用的结论>。依据：<实际文档章节、代码位置或验证记录>。
- <影响结果的分支或例外>。依据：<对应证据>。

## 未核实范围

<仅在影响适用性时说明缺口。>
```

- 聊天中用户确认的设计约束、静态代码观察和实测分别归因。保留实际使用过的卡 ID、原件和验证记录。关键实现结论写直接源码依据。
- 源码依据使用实际模块及模块相对路径、符号或行段和核实版本；需要时补仓库位置。工作区内容无法绑定提交时以实际文件摘要说明观察范围。未知宏、构建条件、跨端与运行行为保留为未知。
- 较复杂的流程可加图。保留能解释结论的关键入口、分支和出口，正文用短编号复用同一个依据时保持对应清楚。

## 保存原稿与配图

无独立配图时保存一份 UTF-8 Markdown，不创建资料包标记。引用应从原稿所在位置可解析；短文本证据可摘录到稿内并保留真实来源，不依赖临时目录。内嵌的有效 data URI 图片可以保留。

需要保存独立配图时，用普通文件工具将主稿和实际图片放入 `docs-raw/agent-notes/<主题>/`，例如主稿 `note.md` 使用指向 `assets/a.png` 的相对图片引用。沿用已有资料包标记 `.intake-package.json`，只指定这一份主稿。下列结构中的大小和摘要必须替换为实际值，大小为整数：

```json
{"schema_version":"1.0","document_path":"note.md","files":[{"path":"note.md","size":0,"sha256":"<SHA256>"},{"path":"assets/a.png","size":0,"sha256":"<SHA256>"}]}
```

`files` 列出主稿与每份配图，路径相对主题目录。复制真实文件后，用文件工具计算每份实际字节的大小和 SHA-256，最后写标记；不要估算或手填摘要。回读主稿并核对本地图片均存在，缺图时说明缺口，不交付为完整稿。后续入库只交接 `docs-raw/agent-notes/<主题>/note.md`，配图由既有解析流程随主稿读取。
