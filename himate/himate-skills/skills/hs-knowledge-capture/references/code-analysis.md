# 源码原稿

从实际知识根的 `config.yml` 确认模块与代码目录，沿用请求中的入口和问题。在相同执行端用普通搜索、文件读取工具定位定义，阅读关键实现及必要调用上下文，不能只凭搜索摘要编造调用链。

同名入口优先用已给模块、文件、调用上下文消歧；仍有多个会改变结论的候选时，展示必要区别并询问用户。范围清楚时直接分析，不再询问已提供的知识根或是否允许生成草稿。

读到足以回答当前问题的关键判断、分支、出口和相关调用即止。说明调用条件、异常返回与资源/状态交接；图用于解释实际流程，不补不存在的跨端调用。宏开关、构建条件、运行时或硬件行为未核实时保留未知，不能把静态返回值写成实际传输成功。

引用保留实际模块、相对路径、符号或行段，以及核实的提交或文件摘要。写清路径基准，不把模块相对路径当成相对原稿的链接；有真实可打开的链接时再提供。工作区未提交改动不能直接归于 HEAD。版本变化影响结论时重新核对所需范围，说明采用哪一版。

无需为了写原稿登记源码来源、创建卡或运行巡检。复杂问题可按用户关心的路径补图，重点仍是依据和适用边界。
