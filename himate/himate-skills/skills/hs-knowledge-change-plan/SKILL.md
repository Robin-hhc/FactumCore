# 制定简短编辑计划

复用 Workflow 已确认的知识根、执行端和工具命令前缀。独立使用时从宿主或部署配置确认该执行端的工具入口，读取知识根的 `AGENTS.md` 和 `config.yml`，以知识根为工作目录，用该入口运行 `doctor --knowledge-root <知识根绝对路径> --json` 核对目标和工具版本。后续示例中的 `knowledge` 代表该已确认的入口，每次调用都传入同一 `--knowledge-root`，工作目录为知识根。

## 代码巡检的编辑计划

读取 `.build/task.json`。有 `task.code_review` 时，以 `affected_cards` 为范围，逐卡核对引用该文件的段落。仅在原 ID 和正式路径更新已有卡，修复定位、结论或适用条件，或在整卡职责确实失效时保留原卡并说明退役依据。保持每张卡的知识边界，计划的 `cards` 只列本批要更新的卡及其必要代码引用，删除清单为空。

- 缺少复核基线时，逐条确认当前代码对原结论的支持并记录依据。有可信旧版时再比较变化。
- 仅定位变化时，用唯一核实的符号修正行段，保留仍成立的结论。行为变化、源码删除或失效引用时，核对结论及条件，再决定修复证据、更新结论或退役。必要依据无法核实时暂缓。
- 逐卡复核后无改动，写 `cards: []` 和无改动理由，仍交 P4。遇到独立新主题，在计划正文单列主题和证据位置，交接给 L4 汇报。

代码巡检按以上范围形成短计划。包含代码分析的文档仍按文档入库规则处理。

## 文档及普通入库的阅读和决策

1. 先读 `.build/task.json` 和完整关联卡。有 `document_review` 时，从 `index_ref` 查看单元和原件定位，读 `packet_ref` 内拟评估的小段。结合上下文与图表选实际结束单元，起点为 `start_unit`，结束不超过 `end_unit`。以 `markdown_ref` 所在目录打开 Markdown 中的图片，结合相邻 OCR 检查关键数值和条件。已评估范围涵盖选定单元的全部内容。
   旧 PDF task 依据 `pdf_review` 选实际物理页。其它文档沿用原材料范围，代码来源按被引用段落评估。补读其它范围可用于核实依据，实际审阅范围以计划为准。
2. 按知识主题确定卡片边界，不以来源文件或文件格式划分。决定哪些卡更新、哪些保持；从本轮材料识别值得沉淀的主题，按主题、接口或实体查重，不沿用前一次问答的主题作为筛选条件。
3. 选择 `create/update/merge/split/deprecate/defer`。普通更新保留卡 ID 和原生命周期；状态变化和必要的标签调整在 P2 明确决定。局部过时只修对应结论；合并／拆分交代旧知识去向，依据不足明确缺口。
4. 在 `.build/plan.md` 的 YAML frontmatter 用 `cards` 固定各候选的 `id`、`knowledge/...md` 正式 `path` 和 `required_code_refs`。有 `document_review` 时写实际 `source_units: [[start, end]]`。旧 PDF task 写 `source_pages: [[start, end]]`。每次只确认从本轮起点开始的一个连续范围。无产卡写 `cards: []`，同时保留实际评估范围。
5. frontmatter 后用自然语言说明本文件主要主题，以及卡动作、结论怎么变、条件与依据、需要保留什么。旧卡结构中的有效条件、历史依据及关系须安排迁入对应正文，不能因简化而丢失；无须提前写完整正文或抄一遍所有未变结论。
   从本轮实际读过的范围提取本卡会使用的真实函数、宏、结构体和文件。为支持关键结论或供读者回查的入口、分支、出口逐项填写 `required_code_refs`。同一文件的不同关键符号各列一项。设计卡使用真实源码作为回查入口时也填写。正文计划说明各位置对应的结论或入口及其适用模块。纯文档卡填写 `required_code_refs: []`，在计划正文写清文档依据。源码会改变本步决策时先核对，并把已核实的位置和观察交给 P3。

完整评估本批材料后无增量，说明理由并交后续审阅和登记。余下单元由下一轮继续。必要范围未读或依据仍有缺口时暂缓。

`task.source.kind=code` 且未启用巡检复核时，逐一评估关联卡中引用该文件的段落，交接已核实的版本与位置。

交 P3 的是计划路径和实际材料入口。计划决定变化时在 P2 同轮修订；不创建冻结版本、前序视图或通过票据。决策和计划格式见[六决策与短计划](references/request.md)。
