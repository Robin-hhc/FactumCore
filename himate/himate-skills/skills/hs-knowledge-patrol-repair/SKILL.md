# 修订已有引用卡

在本轮已确认的知识根和执行端读取材料并写本轮暂存文件。首次单独使用时，先读取知识根的 `AGENTS.md` 和 `config.yml`，用当前会话提供的 `knowledge_doctor` 或已确认 CLI 的 `doctor --knowledge-root <知识根绝对路径> --json` 核对目标。命令找不到、启动入口有明确缺项或诊断仅表明缺运行依赖时，加载 `hs-knowledge-setup`，在同一执行端补齐并复查。得到与知识根匹配的就绪回执后继续原任务。

读取 `.build/task.json`、其中的 `affected_cards` 原卡、实际材料和可用的 `evidence_states`。本节点处理 prepared 语义任务；程序已准备的 mechanical 任务交回 L3 核对分流，不自行改模式。代码任务围绕 changed、unresolved、unversioned 引用核对结论、适用条件及必要上下文，同一卡相关来源一起核对；文档删除任务核对当前缺失和实际历史依据。按[维护候选格式](references/maintenance-candidates.md)记录简短决定和完整候选。

- 语义任务中的定位候选仍须核对引用对象及必要上下文。存在 `location_candidates_ref` 时读取实际候选，其 `requires_context_review` 表示尚需内容核对；不能自行当作机械通过。确认只修位置时保留原结论；若正文重复了当前源码的行号，核对后改用 `code_id`、符号或片段用途关联，行段只保留在 `code_ref`，避免下次插行又过期。固定历史版本的位置保留其版本归属。文件 hash 变化、行号合法或一小段文字相同都不足以单独证明结论仍成立。
- 相关行为变化时，仅修该卡受影响的结论、条件和引用。保留原 ID、路径、知识边界、有效历史文档依据及无关内容。历史原稿与当前代码结论不同时，在受影响正文就近区分原稿记录的历史结论和当前代码结论，注明已核实的版本范围并分别引用依据，不能只靠不同 hash 暗示差异。不改历史原稿，不编造版本、变更原因或运行验证；没有相关语义差异时不硬加迁移说明。
- 缺 evidence_version 的 unversioned 引用逐卡确认当前代码对既有结论的支持，有可信旧版才作历史比较。结论成立且定位正确可以零改正文，仍记录实际核对依据并交 L5，由程序捕获并保存已核验版本；不手写指纹或继承其他引用/文件的版本。
- unresolved 或来源缺失时先核对实际可用的依据。按证据更换当前引用、移除失效当前引用或保留有效历史快照，不能只换版本标签消除待办。局部失效只修对应部分，整卡职责确实失效才说明退役依据。必要证据无法核实时记录具体缺口并暂缓。

卡片的数值或行为结论若依赖函数外的宏、变量、枚举或外层条件，核对决定结论的实际位置并补齐必要引用；不递归收集无关调用链。片段指纹相同只表示显式证据未变，不补足遗漏的依赖。

同文件内独立新主题记录主题和实际证据位置供汇总。维护任务不新建、合并、拆分或物理删除卡片，不改原 ID 和正式路径。只在 `.build` 写候选，正式库由 L6 发布。

决定和候选齐备时交 L5。能由重新备料解决的输入问题交回 L3，无法恢复的必要证据缺口交汇总并保留待办。
