# 独立审阅关联卡维护

沿用本轮已确认的知识根和执行端。当前会话提供本步骤所需的 Knowledge MCP 工具时，调用该工具并沿用其绑定的知识根。采用 MCP 时，缺少工具则报告工具名，调用被拒、失败或返回 `blocked` 时按实际诊断处理。

采用 CLI 时，从知识根运行该执行端已确认的 `knowledge` 入口，每次传入同一 `--knowledge-root`。首次单独使用 CLI 时，先读取知识根的 `AGENTS.md` 和 `config.yml`，运行 `knowledge doctor --knowledge-root <知识根绝对路径> --json` 核对目标和版本。命令找不到、启动入口有明确缺项或诊断仅表明缺运行依赖时，加载 `hs-knowledge-setup`，在同一执行端补齐并复查。得到与知识根匹配的就绪回执后继续原任务。

先确认任务为 semantic（旧任务可缺省）；mechanical 任务应由 L3 的实际分流进入 L6，不在本节点伪造一轮内容通过。由独立 reviewer 调用 `knowledge_maintain_check`，使用 CLI 时运行 `knowledge maintain check --json`。固定检查通过后，结合任务、可用的 `evidence_states`、逐卡决定、原卡、候选差异和实际证据核对以下事项。

1. 修改仅涉及任务关联卡，原 ID、路径和知识边界保留，没有新卡、无关卡或物理删除。
2. 引用定位真实且支持对应结论，适用条件及有效历史依据未因修订丢失。语义任务中的定位修复还须核对引用对象及相关行为依据；函数外决定结论的宏、变量或条件不能因入口指纹未变而遗漏。
3. 历史原稿与当前代码结论有差异时，受影响正文明确区分原稿记录的历史结论和当前代码结论，版本范围及各自依据可回查，原稿未被改写，没有编造版本、变更原因或运行验证。只有 hash 或行号变化、相关语义未变时，不强求迁移说明。
4. `cards: []` 时仍核对本任务固定卡片及引用的当前证据，确认无需改正文的理由充分。unversioned 只表示尚无已核验版本，不预设结论失效或必须产卡。版本由程序在确认后保存，不手填 evidence_version 或把未解决引用标记为 fresh。
5. 正文没有重复当前源码的可变行号；实际行段集中在 `code_ref`，正文通过 `code_id`、符号或片段用途回查。发现过期或重复的当前位置时回 L4 核对改写，不能以指纹相同批准零修改。明确属于固定历史版本的定位保留其版本归属。

在 `.build/review.md` 记录实际检查、逐卡结论、证据位置及缺口。机器通过不代替内容审阅。必要内容均已核实才交 L6，L6 不重复本轮内容审阅。

候选或内容问题带具体依据退回 L4。来源再变或可由重新备料解决的输入问题退回 L3，必要证据不可恢复时交汇总并保留待办。独立新主题只随报告传递，不安排立卡。
