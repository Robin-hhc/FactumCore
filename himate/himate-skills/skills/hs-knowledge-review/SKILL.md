# 检查并独立审阅候选

复用 Workflow 已确认的知识根、执行端和工具命令前缀。独立使用时从宿主或部署配置确认该执行端的工具入口，读取知识根的 `AGENTS.md` 和 `config.yml`，以知识根为工作目录，用该入口运行 `doctor --knowledge-root <知识根绝对路径> --json` 核对目标和工具版本。后续示例中的 `knowledge` 代表该已确认的入口，每次调用都传入同一 `--knowledge-root`，工作目录为知识根。

## P4

1. 先运行 `knowledge ingest check --json`。机器核对计划与候选、格式、有效引用，以及固定原件和本批 `source_units` 或旧 PDF 的 `source_pages`。`PLANNED_CODE_REF_MISSING` 指出某张卡的计划位置未被有效引用覆盖，成稿漏填或错填回 P3，所需依据不足回 P2。范围和计划填写问题回 P2，候选漏写、多写或偏离清单时回 P3。
2. 独立 reviewer 对照 `index_ref` 和计划阅读实际范围，打开 Markdown 中决定结论的图像，路径以完整 `markdown_ref` 所在目录为准。核对正文、图片与相邻 OCR、关键事实和遗漏，再检查旧知识迁入与生命周期决定。必要上下文按需补读。
   核对计划是否列齐候选用来解释行为或用于回查的真实代码位置，包括设计卡里的实现入口。遗漏重要位置的计划回 P2。沿已登记路径和行段核对每条段旁引用、模块与版本，判断能否支撑对应结论。定位不足、歧义或冲突影响结论时补查，并核对原文中应保留的条件和例外。处理代码来源时，逐一核对关联卡引用该文件的段落；即使候选为空，仍检查原结论、条件和定位是否有效。
   复用 task 指向的同一份转换稿、JSON 和图片，不重新转换后当作作者已读材料；机器发现产物丢失或摘要变化时停止核对并重新备料。涉及图的结论实际看图，结合 OCR 文本及原文定位复核，记录未审图片/页段。
3. 在 `.build/review.md` 记录实际结论、选定范围、无增量判断和缺口。必要内容均已核实后交 P5。剩余单元由后续批次处理。

- 决策、事实、条件或归卡问题回 P2。
- 表达、格式、引用填写、路径拼写或组稿问题回 P3。
- 返工稿重跑固定检查，独立核对修改及受影响的结论，结论与依据均未变的部分复用本轮已有的独立审阅结果。缺依据说明缺口，不能写成通过。

P4 是唯一独立 reviewer；P5 直接入库，不重复这轮质量检查。必要的审阅要点见[内容复核](references/review-guide.md)。独立检查正式库使用 `knowledge lint --json`。
