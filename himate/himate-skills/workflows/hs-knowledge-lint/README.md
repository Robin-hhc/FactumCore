# 知识治理巡检 Workflow

串行执行 L1 同步与 L2 扫描，在进入内容处理前确定任务类型。新建、修改或未完成的文档进入 P1–P5，已有卡的引用与结论维护进入 L3–L6，只有派生索引待办时进入 L7，最后由 L8 汇总。外部系统负责周期触发。

| 节点 | Skill | 执行与交付 |
|---|---|---|
| L1 同步 | patrol-sync | 确认知识根、执行端与工具版本，按配置同步 |
| L2 分流 | patrol-plan | patrol plan 返回真实任务，交接来源身份、变化和固定任务类型 |
| P1–P5 文档入库 | source / change-plan / view-materialize / review / apply | 按文档阅读范围备料、主题决策、写卡、独立审阅和发布 |
| L3 维护备料 | patrol-prepare | maintain prepare 固定来源版本、关联卡和当前及历史证据入口 |
| L4 关联卡修订 | patrol-repair | 在原 ID、路径及知识边界内修订引用、结论和条件，或给出逐卡零修改依据 |
| L5 独立审阅 | patrol-review | maintain check 加独立内容核验，定位候选和零修改结果也须审阅 |
| L6 维护发布 | patrol-apply | maintain commit 发布已审维护批次，登记实际复核结果及索引变化 |
| L7 索引 | patrol-reindex | 刷新派生索引，不推进来源内容处理事实 |
| L8 汇总 | patrol-complete | 按真实回执报告完成内容、独立新主题、失败和剩余待办 |

L2 的 needs_ingest 仅用于新建、修改或未完成文档，next_file.task_type 为 document_ingest。needs_maintenance 的任务类型为 card_maintenance，包含被正式卡引用的代码缺复核基线、代码或引用变化、代码缺失，以及原文删除后的关联卡复核。未被正式卡引用的代码不成为文档入库待办。来源身份、输入版本与允许修改的卡片由 CLI 根据实际登记和正式引用确定。

P1–P5 保留文档主题发现、查重和新卡创建能力。文档需要源码佐证时仍核实并填写 code_ref，但代码本身不作为这条链的主来源。PDF、DOCX、XLSX 按最早未审阅单元交接有界候选，P2 选择连续范围，P4 独立审阅后由 P5 登记实际覆盖。P5 成功回 L2，下一份或剩余文档范围由 L2 再选择。

L3–L6 维护固定集合的已有卡，不新建、合并、拆分、移动或物理删除卡片。仅定位变化须有可信旧证据、唯一新位置，并确认相关行为和条件未变；CLI 的定位候选仍经过 L5。行为变化时复核受影响结论及条件，保留历史文档依据和未受影响知识。缺复核基线先核验当前引用和结论，不等同于整份代码未入库。代码中的独立新主题仅由 L8 报告，不在本次维护立卡。

P4 和 L5 均由独立 reviewer 执行，其他节点为 coder。P4 的问题回 P2/P3，L5 的内容或候选问题回 L4，可通过重新备料解决的输入问题回 L3。永久证据缺口直接交 L8，保留待办。零修改维护仍经 L5 核验并由 L6 登记复核结果。

P5/L6 可恢复的执行错误通过 retry 保留原批次重试，不重新扫描。确认未发布且需改稿时回本分支作者节点，重新经过独立审阅。L6 确认未发布但来源版本失效时回 L3。无法确认发布状态或当前无法恢复时走 failed，保留现场并报告。来源再变时旧批次不得发布。

P5、L6、L7 成功都回 L2 重新观察，选定来源单独返回 unchanged 也回 L2，不据此认定整轮已清空。L8 分别解释文档阅读进度与关联卡复核结果，不将代码维护回执表述为全文入库完成。

没有嵌套 Workflow，也不并发运行另一个 ingest。workflow.yaml 维护实际节点、角色和出口，layouts.yaml 维护两条内容分支的画布位置。节点操作细节由各自 Skill 提供，Git 提交与推送按用户授权执行。
