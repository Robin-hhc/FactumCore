# 知识治理巡检 Workflow

按串行运行设计：L1 同步、L2 找待办、L3 刷索引、L4 汇总；内容处理复用 P1—P5，沿用 P2 路径和状态决定、P3 完整知识保留、P4 独立审阅、P5 不复检与直接重试职责。外部系统负责周期触发。

L2 用 `patrol plan` 选择待办，返回 `next_file.source_id`。P1 用该 ID 准备一份 raw 或已登记的代码文件。PDF、DOCX、XLSX 的未审阅范围也属于待办。P1 准备或复用完整稿，再从最早未审阅单元交接有界候选。P2 选择连续范围，P4 审阅后由 P5 登记。P5 成功后回 L2 按当前进度继续选取。P1 返回 `blocked` 或 P2 暂缓时，L4 报告原因和剩余事项。

P1 若发现 L2 选定的来源已无待办，返回 L2 重新选择；单一来源无待办不代表本轮巡检已清空。共享 P1/P5 遵循巡检调度，成功回 L2，不套用独立 ingest 的 P5 回 P1 范围循环。

仅索引问题进入 L3；L2 确认无待办进入 L4。L4 统计剩余事项，不另建全库水位。同步仅执行配置的 argv/cwd；内部 MM 只适配同步，子仓历史使用原生 Git。

没有嵌套 Workflow，也不并发运行另一个 ingest。WiFi 巡检细节见知识根的 `docs-llm-wiki/知识库详细设计.md` 第 3.1 节。
