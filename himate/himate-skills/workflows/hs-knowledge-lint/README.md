# 知识治理巡检 Workflow

串行执行 L1 同步与 L2 扫描，在进入内容处理前确定任务类型。新建、修改或未完成的文档进入 P1–P5，已有卡的引用维护由 L3 按程序观察分流：定位修复直交 L6，语义维护经 L4/L5 再发布。只有派生索引待办时进入 L7，最后由 L8 汇总。外部系统负责周期触发。

| 节点 | Skill | 执行与交付 |
|---|---|---|
| L1 同步 | patrol-sync | 确认知识根、执行端与工具版本，按配置同步 |
| L2 分流 | patrol-plan | patrol plan 返回真实任务，交接来源身份、变化和固定任务类型 |
| P1–P5 文档入库 | source / change-plan / view-materialize / review / apply | 按文档阅读范围备料、主题决策、写卡、独立审阅和发布 |
| L3 维护备料 | patrol-prepare | maintain prepare 固定引用状态、相关来源与已有卡范围，机械任务交 L6，语义任务交 L4 |
| L4 关联卡修订 | patrol-repair | 在固定语义任务范围、原 ID 及路径内修订结论和引用，或给出零正文改动依据 |
| L5 独立审阅 | patrol-review | maintain check 加独立内容核验，语义任务的定位候选和零正文改动也须审阅 |
| L6 维护发布 | patrol-apply | maintain commit 区分程序机械凭据与真实 L5 通过，重验固定输入后发布 |
| L7 索引 | patrol-reindex | 刷新派生索引，不推进来源内容处理事实 |
| L8 汇总 | patrol-complete | 按真实回执报告完成内容、独立新主题、失败和剩余待办 |

L2 的 needs_ingest 仅用于新建、修改或未完成文档，next_file.task_type 为 document_ingest。needs_maintenance 的任务类型为 card_maintenance，包含当前代码引用的 relocated、changed、unresolved 或 unversioned 待办，以及原文删除后的关联卡复核。fresh 引用不因文件其他内容变化而成为内容待办；未被正式卡引用的代码不成为文档入库待办。来源身份、输入版本与允许修改的卡片由 CLI 根据实际登记、正式引用和逐引用版本确定。

P1–P5 保留文档主题发现、查重和新卡创建能力。文档需要源码佐证时仍核实并填写 code_ref，包括决定结论的必要宏、变量和条件；代码本身不作为这条链的主来源。evidence_version 由程序在实际检查时捕获，在同版正式发布时保存，AI 不手填。PDF、DOCX、XLSX 按最早未审阅单元交接有界候选，P2 选择连续范围，P4 独立审阅后由 P5 登记实际覆盖。P5 成功回 L2，下一份或剩余文档范围由 L2 再选择。

L3–L6 维护程序固定的已有卡和引用，不新建、合并、拆分、移动或物理删除卡片。L3 实际返回 mechanical_prepared、task.mode 为 mechanical 时，程序计划和候选直接交 L6；原 commit 重验 mechanical_check_ref、固定输入和仅定位差异，不伪造 L5 内容通过。prepared 语义任务进入 L4→L5；任一引用需要语义判断时，同一卡相关来源和定位候选一并进入该任务，不能拆为两路覆盖。

行为变化时复核受影响结论及条件，保留历史文档依据和未受影响知识。unversioned 或兼容的 baseline_missing 先核验当前引用和结论，不等同于整份代码未入库；成功后由程序记录已核验版本。片段指纹表达显式证据是否变化，不证明所有间接行为等价。代码中的独立新主题仅由 L8 报告，不在本次维护立卡。

P4 和语义任务的 L5 均由独立 reviewer 执行，其他节点为 coder。P4 的问题回 P2/P3，L5 的内容或候选问题回 L4，可通过重新备料解决的输入问题回 L3。永久证据缺口直接交 L8，保留待办。语义任务零正文改动仍经 L5 确认，再由 L6 保存实际核验的版本；机械任务不额外启动 L4/L5。

P5/L6 可恢复的执行错误通过 retry 保留原批次重试，不重新扫描。确认未发布且语义候选需改稿时回本分支作者节点，重新经过独立审阅。L6 的机械凭据/允许差异不成立或输入已失效时，确认未发布后回 L3 重备料，不手改模式或凭据。无法确认发布状态或当前无法恢复时走 failed，保留现场并报告。来源再变时旧批次不得发布。

P5、L6、L7 成功都回 L2 重新观察，选定来源单独返回 unchanged 也回 L2，不据此认定整轮已清空。L8 分别解释文档阅读进度与关联卡复核结果，不将代码维护回执表述为全文入库完成。

没有嵌套 Workflow，也不并发运行另一个 ingest。workflow.yaml 维护实际节点、角色和出口，layouts.yaml 维护两条内容分支的画布位置。节点操作细节由各自 Skill 提供，Git 提交与推送按用户授权执行。
