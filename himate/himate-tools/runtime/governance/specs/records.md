# 来源处理事实与运行记录

## 需要保留的事实

程序在正式来源登记中保存来源ID到实际路径的映射、文件存在性、上次完整成功处理的SHA-256以及必要时间/来源Git定位。卡片保存引用事实，数据库提供双向查询；已有卡引用不能代表整份文件处理完成。

PDF、DOCX、XLSX 的 `processing` 可记录同版原件的已审核阅读单元：

```yaml
processing:
  source_sha256: <本次原件的SHA-256>
  review_sha256: <阅读稿与分段身份>
  reviewed_units: [[1, 42], [79, 96]]
```

完整物理页一一对应的 PDF 可保存 `source_sha256` 和 `reviewed_pages`。读写时校验摘要和正整数区间，返回排序合并的范围。重建数据库从正式来源登记恢复。

覆盖表示范围内全部材料已评估、通过 P4 并完成 P5。原件换版后从头开始。来源删除时清理失效进度。

完整审阅且无增量的批次凭实际理由登记。只有全文覆盖才登记成功摘要并移除 `processing`。显式重新评估的首批前仍保留旧成功事实。只为当前选中的来源登记本批覆盖。

## 本轮交接

P1 保存本版原件与完整转换描述符，交接 `task.document_review` 的候选。P2 在计划记录实际 `source_units`，P4 记录实际核对结果，P5 仅登记选定范围。批次暂存位于 `.build`，转换缓存位于 `artifacts`，正式进度写来源登记。

转换材料通过 manifest-reference 交接身份、摘要与入口。`blocked` 交接 P1 缺口和定位，修复后的转换方可开始本轮审阅。

P5 核对本轮材料与范围，写卡并更新索引后登记覆盖。失败保留现场供同批重试。重复登记按区间并集计算。

本批成功返回 `completed`，`source_complete` 指明全文是否完成。部分完成的回执提供 `processing` 和 `remaining_units` 或 `remaining_pages`。独立入库在原始范围内回 P1 续办，巡检回 L2。转换阻塞保留待办并报告缺口。

不增加前序通过票据、不可变视图链、CAS、应用层journal或备份链。数据库可用常规事务完成自身更新，不宣称外部文件与数据库在所有故障下原子完成。串行运行、Agent重试及必要时人工恢复是初期选择。

## 历史兼容

现有schema_version 2.0、operation、publication或completion等历史记录保留原字节供明确读取，不重签、不批量搬迁。它们不成为新单文件入库的前置；新流程也不继续生成旧阶段状态图。

运行摘要、格式或索引成功不认证Agent身份，不证明内容语义、代码适用条件或访问权限。P4独立审阅、固定检查和实际宿主验证分别说明范围。
