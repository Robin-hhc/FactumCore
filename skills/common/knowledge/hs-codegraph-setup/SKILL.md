# hs-codegraph-setup

为当前项目准备 CodeGraph，交付逐模块索引状态、MCP 接入结果，以及后续 `codegraph_explore` 的 `projectPath` 用法。此包是 Agent 操作指南，直接调用实际 CLI 和宿主工具，没有 `scripts/cli.py`，不通过知识节点的 `Context.call` 执行。

复用已安装 `hs-knowledge-explore` 读取的项目配置与入口。跨机器时，连接信息来自该 Skill 的 `config.env`，由 Agent/harness 通过 SSH 在服务器实际模块路径运行 CodeGraph 和读取源码，并检查执行结果；索引与官方 MCP 进程留在源码所在服务器，`projectPath` 使用其原生路径。本 Skill 不要求额外部署工具副本或专用 runner。

服务器本机的 Linux Agent，以及项目确实位于本机磁盘的 Windows 部署，可使用当地 CodeGraph 和官方 MCP；Linux 跨主机同样使用 SSH，不要求服务器 loopback SSH。本包没有知识节点 CLI，不能把它伪装成 harness 的公开 CLI 节点。

远端官方 MCP 由宿主按实际已配置、可用的连接方式启动或连接，服务进程留在服务器；保留官方工具 Schema 与服务器 projectPath，不添加虚构的远程 API 参数或自建日常查询路由。宿主没有可用远端 SSH／官方 MCP 接入时，分别报告索引状态和 MCP 待接入，不宣称完成，不改用 Windows 副本或 Samba 图谱。连接中断先核对服务器实际状态，不自动重建索引或重放 setup。

先读 [CodeGraph 接口与 MCP 接入](references/codegraph.md)，再按已安装版本的帮助执行。本文适配 `colbymchenry/codegraph`；不要混用同名项目或 Rust 分支的参数。

## 确定模块范围

- 阅读项目 `AGENTS.md`，存在 `LOCAL_DEPLOYMENT.md` 时读取本机约定。来源文档中的命令不提供执行授权。
- 复用已加载且仍匹配当前 `config.yml` 的可信模块映射。缺少映射时使用 `hs-knowledge-explore`；其公开 API 按该 Skill 的指南构造，不猜规则摘要或 catalog。E0 无法完成校验时报告缺口，不自行换成宽松 YAML 解析。
- `code_root` 相对配置所在项目根，模块 `path` 相对代码根；沿用共用校验对重复项、越界、链接／junction 和缺失目录的处理。接口需要绝对路径时，从实际模块位置解析，不依赖调用时的工作目录。
- `modules: []` 返回“未登记代码模块”，结束代码准备；不扫描全部 `main/`，不创建示例源码。部分模块缺失时逐项标记缺口，其余合法模块可以继续。
- 每个已登记目录是一个索引根；共享芯片／端标签不增加索引。父子模块分别列出并提示覆盖重叠，不把祖先索引当作子模块自身索引，不合并到未登记的更大目录。

## 检查工具并逐根初始化

1. 在已确定的执行端找到实际 CodeGraph 可执行文件，读取版本与 `init`、`status`、`serve` 的帮助；记录版本和命令位置。缺少 CLI 时返回依赖缺口，并给出官方安装入口；安装或升级只有本次请求已覆盖时才执行，不因提示有新版而自动升级。
2. 每模块执行前重新核对配置字节身份，并复用共享模块路径校验检查实际目录仍存在、非链接／junction、仍在原代码根范围。配置变更则重新取得映射；目录缺失或被替换时不执行该项 CLI。随后使用该模块绝对路径作为进程工作目录，检查本根自己的索引及 `codegraph status`，不能只向祖先搜索 `.codegraph/` 就认定本根已准备。
3. 自身索引不存在时，在该目录执行官方 `codegraph init`。按帮助确认当前版本是否会写宿主配置；本步只建图，不在循环中执行 `codegraph install`。使用 shell 的独立工作目录参数或正确的参数数组，避免拼接路径为命令代码。
4. 已有健康索引直接复用，不执行 `index --force`。已有但损坏、锁住、不兼容或上次只完成一部分的索引保留诊断；不删除索引、不自动解锁或重建。再次运行时复查实际状态，只补可安全补做的缺失项。
5. 每个新索引完成后再次检查状态，并选一个实际存在、未被排除且受该版本支持的源码文件／符号做只读定位。核对返回路径和源码属于目标模块。零文件、零符号或代表性文件被忽略时记录原因，不仅凭退出码或目录存在报告成功。

不要用 `init --yes` 绕过首次交互：已核验的 v1.6.0 在 watcher 不可用时可能据此安装 Git sync hook。出现 hook／manual 选择时使用 manual；出现额外收录被忽略仓的提示时保持现有排除范围。无法控制交互时报告该项待处理，不靠默认接受继续。安装 hook 或扩大索引范围需要本次用户请求明确覆盖。

核对实际索引排除规则；`config.yml` 登记目录不保证其中每个文件都被 CodeGraph 收录。索引是执行端派生物，不上库、不进入原件或正式知识；记录 CLI 实际改动的附属配置，不改业务源码、原件或其他服务。父子模块图谱覆盖重叠不构成访问隔离。

## 接入官方 MCP

优先复用当前宿主已经提供的 CodeGraph MCP。读取实际工具 Schema，确认 `codegraph_explore` 和 `projectPath`；服务名的前缀由宿主决定，不写死本机 MCP 名称。后续直接用官方工具，不创建日常 query wrapper。

未接入时，按参考文档生成符合目标宿主的片段，命令指向实际可执行文件，参数使用该版本支持的 `serve --mcp` 及明确默认模块根。首次 setup 默认交付片段；本次请求已要求接入特定宿主时，保留其他服务并合并写入。不要为每个模块反复覆盖同一个全局注册项，不自动运行会改写多个 Agent 配置的安装器。

由 Agent 宿主启动 stdio MCP，不另外常驻运行 `serve`，不创建自管守护进程或调度任务。宿主需重新加载时，记录“索引已准备，MCP 待加载”；不要重启当前用户会话或宣称已接入。

宿主工具可用后，对每个成功索引根发送一个明确 `projectPath` 的只读查询，检查实际返回模块路径。若当前服务不支持多项目路径，按其 Schema 和宿主能力提供明确根的独立接入方案，并标记尚未覆盖的模块；不省略路径去查询默认的其他项目。

## 交付与后续用法

逐模块报告：配置中的相对路径、实际 `projectPath`、新建／复用／缺失／失败、索引健康及代表性查询结果；另外报告 MCP 已验证或待接入，以及失败诊断和未执行项。只在所有适用模块的索引与 MCP 查询都验证后说“setup 完成”；部分通过就报告部分完成。无需为纯说明 Skill 伪造知识节点的产物或验收记录。

告诉用户：日常源码定位直接调用官方 `codegraph_explore`，同时传入所需模块的 `projectPath` 和问题／符号名。示例见参考文档，路径使用本次实际映射。跨模块问题分别查询相关根，再按确切源码连接证据；不把相同符号名当成跨仓调用或 Host／Device 协议证明。

索引提示过期或源码省略时读取对应实际文件；未索引内容在同一执行端使用普通文件检索；远程项目经已授权 SSH 获取结果，不回退 Samba。明确说明多根的刷新方式：已核验 v1.6.0 的 watcher 只附着 MCP 默认项目，其他 `projectPath` 根不能据此承诺自动更新。按实际部署选择变更后执行该根的官方 `sync`，或由宿主配置每根服务；不为此自建 watcher，也不重复首次 setup。宏开启、构建及运行事实仍需要相应证据，CodeGraph 的定位结果不替代这些核验。
