# 制定简短编辑计划

在实际知识根执行命令，Linux 使用 `sh ./knowledge.sh`，Windows 使用 `.\knowledge.cmd`；已注册入口可直接用 `knowledge`。位置由 Workflow 首节点确认，独立使用时从当前工作区 `AGENTS.md`、`config.yml` 获取。

## 阅读与决策

1. 先读 `.build/task.json` 确定本轮来源，再读文件副本和完整关联卡；文档按全文评估，前次问答不自动限定本轮主题。旧原文、其它来源和代码按需补读。
2. 决定哪些卡更新、哪些保持；同时检查本次文档新增的重要知识是否已有合适卡容纳，按主题、接口或实体做针对性查重。
3. 选择 `create/update/merge/split/deprecate/defer`。普通更新保留卡 ID，合并／拆分交代旧结论去向；依据不足就明确缺口。
4. 将简短计划写入 `.build/plan.md`：本文件主要主题，以及目标卡、动作、结论怎么变、条件与依据、需要保留什么。无须提前写完整正文或抄一遍所有未变结论。

完整评估后无增量，说明整份来源无需改卡或新增卡的理由，交后续审阅和处理完成登记。仅某个旧主题无增量不足以结束本文件；必要依据仍有缺口时暂缓。

`task.source.kind=code` 时只判断本次代码对关联卡的结论及定位影响。包含代码分析的文档仍按文档全文评估。

交 P3 的是计划路径和实际材料入口。计划可在本轮修订；不创建冻结版本、前序视图或通过票据。决策边界见[六决策](references/request.md)。
