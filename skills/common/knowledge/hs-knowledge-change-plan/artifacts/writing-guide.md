# Writing guide

Report the actual CLI status, phase, diagnostics and returned business file references. Use the output of this invocation; do not invent a passing result. OpenFlow owns run/node/attempt tracking and transition checks.

Identify the fixed material/scan or explicit material targets, exact unit outcomes, normalized record_action/card_refs/claim_refs, Claim comparisons, six card actions and target queries. Do not produce a byte plan or independent review result here.

Explain each query's purpose and actual context in terms of the expected Claim. Positive cases should identify the intended `CardID#ClaimID` when useful; negative cases retain their explicit exclusion or empty-result expectations. Code links do not turn design evidence into implementation evidence. P3 records the authored expectation; P5 tests it against the final candidate.

Plan output is staged. Identify explicitly adopted inputs and final-reference mappings; never claim formal state or choose an old private draft implicitly.
