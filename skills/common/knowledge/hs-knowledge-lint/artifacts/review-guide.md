# Review guide

Check the actual result and relevant card/source/view/index bytes. State unresolved gaps. Workflow order, role assignment and handoff validation belong to OpenFlow. A successful business check does not prove semantic correctness, deployment or Git merge.

Check that every selected active-card code source has code_ref, independently of code_gate or Claim adoption, and report CODE_REF_REQUIRED when absent. Pure documents need no invented code links; inspect the actual content for necessary missing entry points. Historical recovery and deprecated cards keep four-field compatibility. Check declared selectors through the common rules. Preserve the old snapshot/locator and the separate current code_navigation result; ambiguous conditional definitions and unsupported parsing cannot be marked resolved. Existing code/current Claim checks still apply.

For P5 content review, inspect the original frozen cases and their actual candidate-query results, including purpose/context, expected and actual cards/Claims, exclusions, order and same-candidate reads. A failed expectation blocks publication and returns to P3; unavailable inputs remain incomplete. Code links are navigation, not implementation evidence. Formal lint/CI and record-only results must not claim that this private-plan preview ran when it is not applicable.

Reports and code-check copies belong to this operation stage. Report actual checks; do not claim formal evidence was published or clean another task stage.
