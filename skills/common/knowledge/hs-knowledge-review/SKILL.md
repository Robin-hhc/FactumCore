# 独立审阅与质量检查

## 目标与输入

P4 核对作者结论、完整稿件及证据，报告问题和返工位置。接收本次 `view_ref`、对应的 P2 计划、P1 阅读材料及独立审阅任务；不替作者改稿或发布知识。

K 是已确认的实际知识根，在数据所在执行端调用仓内 CLI；入口不明时先用 `hs-knowledge-explore` 定位。

## P4 执行

1. 阅读计划、完整稿和相关新旧原文，检查 Claim 的事实、适用条件、依据及旧结论去向。对实质 skip 等决定按风险抽查，明确已审和未审范围，见[内容复核](references/review-guide.md)。
2. 按[审阅请求](references/content-review.md#p4-请求)填写实际样本、理由和 `findings`。代码或混合稿另按[代码依据](references/code-evidence.md)准备 `code_review`；纯文档不补造代码依据。
3. 调用一次完整审阅：

   ```text
   python K/knowledge.py review --input REQUEST.json --json
   ```

CLI 保存实际审阅声明；内容审阅无阻断后，执行一次完整候选固定检查。内容批还用同次临时索引执行 P2 原冻结查询及同候选精读。读取报告的检查状态和逐例预期／实际结果，不能把“索引可构建”当作查询已通过。

## 完成与返工

| 实际结果 | 交接 |
|---|---|
| 所有适用检查完整执行、无阻断 | 报告确切视图、检查结果和未审范围，交 P5 转写记录 |
| 原文、旧版、代码或配置材料不足 | 给出缺口和位置，返回 P1 |
| 结论、适用范围、归卡或冻结查询预期错误 | 给出依据和理由，返回 P2 |
| 字段、正文、来源登记或导航表达错误 | 返回 P3 |
| 运行、规则或报告不可用 | 保留真实诊断和停点，不能作为通过或空结果 |

新稿重新审阅；输入漂移按实际诊断交回来源节点。P4 不自行调用其他阶段修复问题。仅记录批审阅处置和欠账，不构建内容索引。

## 按需检查

- 独立检查正式库／候选或局部范围：读[独立检查](references/content-review.md#独立固定检查)。
- 独立登记内容审阅或复验代码依据：读[审阅请求](references/content-review.md#独立审阅记录)和[代码依据](references/code-evidence.md#独立动作)。
- 固定 CI 接入：仅在该任务下读[CI 契约](references/ci-contract.md)。

原件只读。CLI 负责引用、字节和规则绑定；独立阅读与技术判断由 reviewer 完成。所有 P4 报告和临时索引留在本批暂存，不切换正式活动索引。
