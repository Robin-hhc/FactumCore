# 检查并独立审阅候选

在实际知识根执行命令，Linux 使用 `sh ./knowledge.sh`，Windows 使用 `.\knowledge.cmd`；已注册入口可直接用 `knowledge`。位置由 Workflow 首节点确认，独立使用时从当前工作区 `AGENTS.md`、`config.yml` 获取。

## P4

1. 先运行 `knowledge ingest check --json`，由机器将计划 `cards` 中的 ID/路径与完整候选一一核对，并检查格式与引用。不另行推断路径类型；候选漏写、多写或偏离清单时回 P3，计划决定本身需改变才回 P2。
2. 由独立 reviewer 先按 `.build/task.json` 阅读本次材料，判断应覆盖的主题或代码影响，再对照计划、旧卡与完整候选核对事实、条件、依据、遗漏及归属。检查旧知识迁入正文是否完整、整卡退役是否成立及状态是否符合 P2 决定；涉及实现时读必要代码。
   复用 task 指向的同一份转换稿、JSON 和图片，不重新转换后当作作者已读材料；机器发现产物丢失或摘要变化时停止核对并重新备料。涉及图的结论实际看图，结合 OCR 文本及原文定位复核，记录未审图片/页段。
3. 在 `.build/review.md` 简短记录实际结论、问题及未审范围。通过后交 P5，不自行改作者稿。

- 决策、事实、条件或归卡问题回 P2。
- 表达、格式、引用填写、路径拼写或组稿问题回 P3。
- 新稿重新检查并审阅；缺依据说明缺口，不能写成通过。

P4 是唯一独立 reviewer；P5 直接入库，不重复这轮质量检查。必要的审阅要点见[内容复核](references/review-guide.md)。独立检查正式库使用 `knowledge lint --json`。
