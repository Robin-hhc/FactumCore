# WiFi 知识入库 Workflow

通过 OpenFlow 编排已安装的知识库 Skill，将新增、变化或待处理原件转为经过复核的本地知识，并支持修订与中断续办。

## 文件

- `workflow.yaml`：节点、执行角色、提示及分支出口。
- `layouts.yaml`：工作流在 OpenFlow 画布中的节点位置。

## 主要流程

1. 扫描六类原件，识别变化、用户修订请求和未完成事项。
2. 准备新旧材料，阅读并制定计划，形成完整候选稿。
3. 独立复核内容，按需核验代码，执行最终完整检查。
4. 登记处理记录并本地入库，完成索引验证、目标查询和活动代激活。

无变化且无待办时直接结束；仅记录批保存记录后结束；中断按实际停点续办。

扫描的 `actionable_unit_ids` 与 `finalization_pending` 分开读取：已入库待索引／查询的批次不重新提炼原件；后者非空或状态不明时不能选择无需更新。通过只读 `status` 核对确切视图、冻结查询、候选代及构建时原 `expected_active`；回归显式传 `view_ref` 或 `apply_result_ref`。缺绑定、旧规则或活动代已变化时先检查，不替换 CAS 基线或重复 apply。完整 no-op 不新增正式记录，也不制造下一次扫描的假待办。

## 使用前提与边界

- 由 OpenFlow 加载模板，安装其引用的 Skill，并配置 `coder`、`reviewer` 角色。
- 先准备项目 `AGENTS.md`、`config.yml` 和运行依赖，确保宿主能访问知识根及核验结果文件。
- 原件和业务代码只读；缺材料或运行异常时保存停点，不当作完成。
- 完成本地入库后，Git 提交、CI 与合入由人后续处理。
